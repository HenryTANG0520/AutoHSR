# 货币战争补给刷新与候选校准

原生Q刷新图标来自既有CN 4.6补给画面`129-supply-options.png`，静态裁切72×71区域，不包含次数、UID或整图。[sources.json](sources.json)记录源图、原清单、坐标、变换、输出哈希和三份旧画面的固定控件文字。游戏美术归HoYoverse及相应权利人；来源记录不授予额外许可，没有新游戏截图或模型训练。

[刷新协议](../../autohsr/currency_wars_standard_supply_refresh.py)使用当前剩余次数、未选状态和独立Q图标共同核实控制。次数支持完整标题或同行分开的标题／数字，范围0～99；局部原图与二值读取须一致且至少0.90，全图矛盾不被覆盖。图标匹配至少0.92并要求明亮控件；顶部或其他区域的数字不能成为刷新目标。每次只点击当前次数控制一次，核对剩余次数恰好减一、完整候选及可见HUD后记录独立回执。候选相同则记`candidates_changed=false`，不伪称变更；未知反馈保留原意图，不重放。每次补给最多五次，默认策略不刷新。

[补给列读取](../../autohsr/currency_wars_supply_fields.py)按完整装备行核对四／五卡布局，再逐列关联角色，不将漏读名字当成卡片减少。缺名可尝试原图／二值局部双读；未达阈值时保留该列的图像签名，未知角色不能被选中。其他可读角色与已识别装备仍可选择；未知装备名称保留在完整候选摘要中，不能作为已知效果领取。刷新后选择、确认分别绑定最后一份已核实候选，实际角色和装备到账继续由原奖励协议逐项核实。

[策略](../../autohsr/currency_wars_supply_policy.py)参考March7thAssistant固定提交的`check_supply_phase`，依据当前持有星级、穿戴与仓库计算阿格莱雅速度装备、核心及支援角色，或希儿缺少的配方材料、核心、进阶装备和支援角色。来源及GPL许可见[上游说明](../upstream/March7thAssistant/README.md)。没有移植连续点击、只排除“0”的刷新或默认中间卡兜底。

三份既有画面实际均为五卡、剩余一次且Q控件可读。129号旧OCR漏掉首张“藿藿”；局部读取仍未达到双读阈值，运行时将其保留为未知列，不猜名称，也不再当作四卡。158及167号五列完整；167号四件进阶装备的效果尚未识别，保留原名。四卡、连续刷新与使用后效果目前只有合成机制检查，**没有独立实机留出或补给刷新验收**。

补给页遮住的金币等HUD字段保持`null`；这里核实的是补给刷新次数，不生成金币零消耗回执，也不改写原始资源记录。已选／确认、暂停／跨运行、账号变化、写账失败、字段冲突或不连续候选均保留原证据。完整验证与剩余事项见[开发记录](../../docs/currency-wars-development.md)。

## 2026-11-05：多装备字段及交付协议

补给字段不再把一个候选的装备限制为单个字符串效果。在原有`.61～.67`装备文字带内，可保留明确以`、`／`+`分隔的两份完整名称，或同一列两份不重叠文字；重复名称保留两件的数量，未知名称保留原文，不拆掉未知部分后选择已知部分。四／五列须完整，低可信、重叠OCR、跨卡、缺列、三件、数量后缀和截断仍拒绝。额外的装备形态文字出现在未校准行时停止，包含未知名称及低可信候选，不把它忽略成单件。

这只是已有文字带内的有界字段协议及合成变体，不是双装备实际布局校准。没有推测带外第二行、第二件图标或坐标，没有读取当前游戏或新增实机截图。现有三份五卡校准仍是单件来源；未知进阶装备和真实双装备页面／交付仍待核实，不用这次字段扩展宣称全补给已支持。

选择、确认及刷新后的候选摘要保存完整原名列表，包含未选中或未知的装备；不能把未知组合统一为`null`后忽略实际候选变化。新选择／确认动作记录`supply_candidate_schema=2`及同一完整表，回执核对最后刷新表与摘要。单件装备仍为旧字符串，两件为明确JSON列表，不去重、不借角色数量或刷新次数推断件数。

新`equipment_delivery_schema=1`回执在返回备战后保持待核对，再完整重采角色；原库存＋同名角色原穿戴＋本次列表，须精确等于新库存＋新穿戴，其他角色不变。支持装备进库存、自动穿戴或分流，以及已知合并后的旧穿戴退库；未核实角色装备不当空。新契约仅支持单张基础拷贝增量及已知三合一合并，直接多星赠送等结果不在此子集，不凭选择数字补造赠送星级；旧单件历史回执按原规则保留。失败或反馈未知不清账、不重发确认。
