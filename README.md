| 挑战次数 | 减号/滑条/加号与整数输入，显示预计消耗；达到总次数即停止，仍受开拓力上限约束 |

项目为非官方社区工具，与游戏开发商、发行商无关联。使用前请了解游戏服务条款及自动化工具的使用限制，自行决定是否使用。

2026-10-20 日常副本选择器已接入当前4.6客户端的104个入口，可在“每日任务”选择分类、副本和地点，通过游戏风格的次数控件设置本次目标。“刷新游戏副本”仅采集指南，不开始战斗。使用与配置兼容说明见 [日常副本与次数](docs/daily-dungeons.md)，实机验证范围见 [验证记录](VALIDATION.md)。下文10月11日花萼验证为历史记录，不代表所有关卡均已逐个通关。

AutoHSR 是面向《崩坏：星穹铁道》的 Windows 每日助手初版。它参考 [BetterGI](https://github.com/babalae/better-genshin-impact) 的屏幕截图、OCR / 图标识别、模拟鼠标键盘输入流程：识别当前页面，执行一个动作，再检查页面变化。遇到未知页面、窗口失焦或验证失败会停止，并保存日志与截图。

用户确定的标准每日路径是**指南 → 指定副本 → 借用好友支援 → 使用已有开拓力刷最多 240**。完整执行标准、永久禁项和小规模测试要求见 [DAILY_FLOW.md](DAILY_FLOW.md)。

本版已实现持续委托奖励领取、六类日常副本挑战、每日实训奖励领取。4.6 的持续委托只领取可领取奖励并核实持续进行，保留原委托，不重新派遣或变更选择。邮件和无名勋礼领取是可选项，默认关闭；已校准当前邮箱入口、领取和禁用状态，以及勋礼本周／本期任务与免费等级奖励页签。软件不会把未确认的奖励或战斗标记为完成。

登录时可处理已拥有月卡的今日补给：核实剩余天数与免费领取提示，领取后核实 90 星琼展示，再关闭展示进入场景。遇到购买、续购、支付或无法确认的奖励卡会停止。

货币战争位于左侧独立页面，沿用日志、暂停/停止及报告入口。“只读识别当前画面”保存截图和文字，不发送输入；未知或冲突页面保持未核实。另提供一次前台3→1换位、所选备战角色到空前/后台的部署验证，以及仅当前节点的出战与结算验证。部署前需核对角色支持所选位置。动作先保存记录，结果不明时不会重放；节点胜利仍返回 `partial`，不代表整局通关。“流程验证：推进当前对局”可串联已核实战斗、结算、位面地图和通用投资策略；升级目标默认“保持”，设置更高等级后每笔购买均核对4金币与4经验，不能确认时只重读或停下。补给可按完整识别的角色与基本装备组合选择并核对高亮；空容量时自动查看角色位置适配并部署，反馈必须同时满足头像、原格清空、人数和金币。出战前检测备战物品与待领晶矿，武装箱和邀请函只处理已校准选项；商店只收起，不把Gemi自身购买计作程序策略。备战席满时可核对同名备战副本后整理，没有可核实副本时停下。完整79页教程、局内攻略及标准/超频经济差异已采集，装备、完整商店策略、终局与整局闭环仍待完成。进展和证据见 [CURRENCY_WARS.md](CURRENCY_WARS.md)。只读命令行入口为 `.\.venv\Scripts\python.exe -m autohsr --currency-wars-check`；货币战争不执行每日任务或修改刷本预算。2026-10-20 随日常副本更新重建 EXE；货币战争仍处于暂停状态。

连续流程还可核实名称与金额后出售场上角色的备战副本，穿戴已校准的电池、防御装备和花火蓄能帆；动作后验证库存、角色原装备、金币与人数。开发对局已取得SSS，程序从统计页返回主页也已验证，但存在手动接续，尚无完整自动整局证据。新增“整局验证：超频A0”显式开局入口，现有“推进当前对局”不会新开一局；未知模式或更高难度会停下。装备合成和完整商店策略尚未开放。

货币战争只读 OCR 已隔离到可终止的子进程；截图同时保存带哈希与完整 OCR 的 `.sample.json`。可用 `--currency-wars-replay "样本.sample.json"` 离线回放，添加 `--replay-ocr` 可重新识别 PNG；两者均不访问游戏或读取每日配置。回放通过只代表样本校验，不代表玩法完成。详细格式、测试与剩余边界见货币战争开发记录。

开发验证若用户要求先静音，可使用独立的 `python -m autohsr.audio` 只读检查；用户明确授权后，`--mute --record-dir "新的记录目录"` 会先保存原状态，再静音活动播放设备并复读核验。该工具不启动游戏、不解除静音、不改麦克风或权限，也不覆盖原状态记录。实际游戏启动仍需单独核实，不能只凭静音成功视为已进入游戏。

货币战争已按用户要求暂停开发，恢复前不继续游戏验证或自动策略执行。已完成内容、实机证据、未验证项和接续点见 [CURRENCY_WARS.md](CURRENCY_WARS.md) 顶部。

## 使用范围

- Windows 10 / 11，游戏语言为简体中文，游戏客户区为 16:9，至少 960×540；建议使用 1920×1080 窗口。
- 采用 Windows DPI 感知、客户区截图和按分辨率缩放的模板。4K 屏幕及系统缩放环境先使用“检测窗口”确认识别结果；运行期间保持窗口尺寸与位置不变。
- 提前完成账号登录、更新和验证码。已登录、停留在“点击进入”画面时，助手可以识别后尝试进入游戏；不会处理密码、扫码、验证码、协议确认或下载更新。
- 预先配置能完成目标副本的队伍，并解锁自动战斗。默认目标是“回忆之蕾 / 城郊雪原”，可在界面选择分类、名称与地点；地点用于区分同名花萼，刷本时必填。保持“借用好友支援角色”勾选，借用好友角色挑战。饰品提取还需已有可用的差分存档。

标准每日仅消耗**已有开拓力**，每次运行上限默认 **240**。首次实机测试请选好副本后点击**测试：1次**，按该分类单次费用填写预算，确认识别和结算正常后再调整次数。上限是一次运行的累计消耗限额，不会自动恢复或购买开拓力。现有量不足时使用可支付的整次挑战，随后停止并报告 `partial` 和实际消耗。

**永久禁止自动抽卡、角色 / 光锥 / 遗器养成、商店、合成、购买和兑换。** 不使用燃料或星琼补充开拓力。出现补充、购买、兑换或需要选择奖励的界面会停止相关操作。配置中的 `allow_stamina_spend=false` 会锁定刷本任务及相关设置；界面没有自授权开关。

## 运行打包版

如果已有 `dist\AutoHSR\AutoHSR.exe`，双击项目目录中的 `Start-AutoHSR.cmd`；也可直接运行该 EXE。保持整个 `AutoHSR` 文件夹完整，不要只复制 EXE。

如果游戏以管理员权限运行，使用 `Start-AutoHSR-Admin.cmd` 并确认 Windows 的管理员提示。它仅以管理员权限启动助手，隐藏启动器控制台，图形界面正常可见；不会更改系统执行策略或其他系统配置。

配置和运行记录保存在 EXE 所在目录的 `config.json` 与 `runs\`，因此请将程序放在可写目录。

源码缺少本地配置时使用 **240 开拓力 / 每批6轮、回忆之蕾 / 城郊雪原、借用好友支援** 的默认值。首次运行请先选择“测试：1次”，核实目标地点后保存或开始；预设本身不会执行任务。仓库不包含打包产物，可按下方步骤自行构建。

## 从源码安装

需要 Python 3.10 或更新版本。`setup.ps1` 默认依次寻找系统的 `py`、`python`、`python3`，创建项目内的 `.venv` 并安装 `requirements.txt`，保留已有虚拟环境。

克隆仓库，然后在项目目录打开 PowerShell：

```powershell
git clone https://github.com/HenryTANG0520/AutoHSR.git
cd AutoHSR
```

安装依赖：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
```

如果使用自选 Python 或应用附带的 Python runtime，显式指定解释器路径；无需修改脚本，也不依赖某个用户名或安装目录：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -PythonPath "C:\path\to\python.exe"
```

这里的 `ExecutionPolicy Bypass` 仅作用于这一次 PowerShell 进程。脚本不会修改机器或用户级执行策略，也不会安装系统级 Python。

安装后双击 `Start-AutoHSR.cmd`，或运行：

```powershell
.\.venv\Scripts\python.exe -m autohsr
```

启动器优先使用打包版 EXE，找不到时才使用 `.venv\Scripts\pythonw.exe` 启动源码界面。

源码更新后已有 EXE 不会自动更新。开发时使用上面的 `.venv\Scripts\python.exe -m autohsr` 明确运行源码，验证后重新构建打包版，再使用启动器。

## 每日执行

1. 启动游戏并完成登录。默认游戏路径为 `E:\miHoYo Launcher\games\Star Rail Game\StarRail.exe`，路径不同可在“启动”页选择。
2. 点击“检测窗口”。助手暂时最小化以让游戏聚焦，完成后恢复界面。“窗口检测”页显示窗口尺寸和助手权限；点击“识别详情”阅读完整 OCR 结果，或点击“查看截图”。
3. 在“每日任务”页勾选任务，填写副本名称与地点，标准每日勾选“借用好友支援角色”。“本轮 240 / 每批6轮”和“测试 10 / 1 轮”只填写开拓力上限与每次轮数，**不会保存或自动执行**。建议首次仅开启委托，或采用测试模式；当前小规模刷本测试地点为“绘世学院”，邮件和无名勋礼仍可保持关闭。
4. 核对启动页显示的副本、地点和**本次运行**开拓力上限，点击“开始每日”。助手最小化，执行中不要移动游戏窗口或操作鼠标键盘。开始只使用表单快照，不写入配置；需要保留方案时单独点“保存设置”。
5. 按 **F9** 暂停 / 继续；暂停时助手窗口会恢复。按 **F10** 紧急停止，也可使用界面的“停止”。关闭助手会先发送停止请求。
6. 结束后查看各项状态、已确认开拓力消耗和每日奖励验证，可点击任务行阅读说明，或打开“最后报告”和“运行目录”。每日实训只有在活跃度与全部奖励状态均获得画面证据后才标记完成。

界面底部会提示未保存的修改，“保存配置”可单独保存表单。未勾选花萼时副本设置会禁用；运行、检测或启动期间设置锁定。执行区显示当前任务、本次耗时和已确认消耗，暂停后可查看详情与记录；停止或异常结束会明确标注未完成、未执行的任务。关闭正在执行的助手会先停止并等待后台退出；关闭前有未保存修改时可选择保存或放弃。

首次 OCR 加载可能需要等待。失焦或最小化时暂停输入并等待前台，不抢焦点；F9 手动暂停仍需手动继续。恢复后丢弃旧截图。战斗中只继续观察当前战斗；若开始挑战输入已中断且消耗待核对，会停止而不重放。窗口移动、未知页面或超时仍需人工核对，不能直接重跑刷本。

## 命令行与记录

```powershell
# 检测与 OCR，只输出 JSON，不点击任务按钮
.\.venv\Scripts\python.exe -m autohsr --check

# 只启动游戏；登录和验证仍需手动完成
.\.venv\Scripts\python.exe -m autohsr --launch

# 按保存配置执行；当前小规模测试使用绘世学院、10 开拓力、1 轮
.\.venv\Scripts\python.exe -m autohsr --run --target "回忆之蕾" --location "绘世学院" --stamina 10 --rounds 1

# 离线单元测试，不启动或操作游戏
.\.venv\Scripts\python.exe -m autohsr --self-test
```

可用 `--config "路径\config.json"` 指定配置文件。源码 GUI 的配置和 `runs\` 在项目目录；打包 GUI 使用 EXE 同目录的配置和记录，两者独立。GUI 仅“保存设置”写入配置，检测、启动和开始均使用内存快照；命令行 `--target`、`--location`、`--stamina`、`--rounds` 覆盖仅作用于本次执行，不写回 GUI 配置。每次运行保存 `run.log`、`report.json` 及关键画面 PNG / OCR 文本，检测结果另存为 `check_...` 目录。首次排查优先查看最新报告中的失败原因和对应截图。

打包版是无控制台的图形程序。使用 EXE 的 `--check` 或 `--run` 时，请读取 EXE 同目录 `runs\` 下的 `check.json` 或 `report.json`；需要终端 JSON 输出时使用上面的源码命令。

## 构建

先完成源码安装，再执行：

构建先写入 `build\package-...` 暂存目录，再复制依赖并最后发布 EXE。重建前关闭已有助手；`dist\AutoHSR` 中的配置与记录原位保留，并另存到 `build\userdata-时间戳`。缺少 PyInstaller 时构建停止，不会自动安装依赖。

## 反馈与贡献

通过 [Issues](https://github.com/HenryTANG0520/AutoHSR/issues) 报告问题时，请附上 Windows / Python / 游戏版本、客户区分辨率、系统缩放、复现步骤及经过脱敏的日志。截图与 OCR 文本可能包含 UID、昵称、好友信息，请检查后再公开。

欢迎提交 Pull Request。修改识别或流程时，请同步维护离线测试和相关文档，并运行 `python -m autohsr --self-test`；涉及 GUI 时还应运行 `python tools/gui_smoke.py`。新增上游素材请在 `assets/ATTRIBUTION.md` 记录来源、版本、修改方式与许可证。未实机验证的场景应明确标注。

## 2026-10-16 UX 更新

两款助手使用相同的“启动 / 每日任务 / 运行日志 / 设置”导航与常驻操作栏，保留各自主题和任务。只有“保存设置”持久化；检测、启动、每日和“仅补领奖”使用当前表单的临时快照。关闭有修改的窗口时选择保存、放弃或取消。检测可停止：等待当前识别返回后丢弃结果，不执行任务。

启动页显示本次计划和已核实的准备条件；未检测或未知权限不会显示为已验证。历史报告标明时间、操作和来源，旧文件时间不等同于游戏日。失败结果同时显示原因、已确认事项、待核对事项和下一步。自动退出单独报告未请求、跳过、已退出或未确认，不覆盖每日奖励验证。

离线 GUI 验收使用 `python tools/ux_smoke.py`（`gui_smoke.py` 兼容入口），所有游戏后端均替换为假对象，配置存于临时目录。此更新没有进行真实游戏任务、资源消耗或战斗验证。

开拓力上限按**每次运行**计算，不是账号每日累计额度。挑战前先将本批消耗写入 `runs/battle-session.json`，成功结算后才从“待核对”转为“已确认”；写入失败不得开始挑战。上次有已确认或待核对消耗且未完整结束时，开始按钮会说明新增预算并要求明确确认，默认取消。记录损坏时禁止新刷本，先人工核对。

“仅补领奖”只验证并领取每日实训，不刷本、不领取附加任务、不修改原方案，也不会清除未解决的刷本记录。请先人工返回可识别的主界面；遗留未知战斗状态不会盲目退出。命令行可用 `--run --reward-only`；明确的新刷本预算使用 `--run --new-battle-run`，先核对上次消耗。当前版本完成后保留游戏，没有自动退出功能。
