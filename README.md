## 体力计划

选择“体力计划”模式后，生存索引中的“加入计划”直接添加该副本及地点，并填写目标次数；已加入的副本显示“编辑次数”。应用后加入本次刷本安排，取消不改计划。该模式下用“调整计划”管理顺序、补刷和共用预算，Esc返回原目录；单副本模式仍使用原来的选择与次数操作。以上更改仅为草稿，“保存设置”才持久化。

“计划后补刷默认副本”一行的“更换副本”直接选择补刷副本、地点和最多次数，不必切回单副本模式。取消保留原目标，应用只改变本次草稿；补刷与刷本开关保持原选择。

多副本在“设置 → 体力计划”选择刷本模式，按分类、名称和明确地点添加条目，可编辑、移除、上移和下移。“按剩余次数”保留同账号原目标的已核实进度，“每次重复”使用原次数；列表中的“目标次数”不会随运行扣减。默认开启计划后补刷，页面显示默认副本及次数；关闭时不执行该补刷。可在同页启用历战优先并选择副本、地点和开始星期，顺序为到期历战→条目→默认补刷。配置完成后仍点击首页“开始计划”，日常结束后处理到期差分／货币周常。只保存过非空列表不会自动启用计划模式；只有“保存设置”持久化当前模式与原目标。

首页在尚未核实当前账号时仅显示目标与共用预算，不显示历史剩余次数。运行中的卡片详情区分此前、本次和本目标剩余；本次预算内结束但长期目标尚有余数时显示“本次安排已结束”。历战结果注明原目标周，读到0次并经后端核实才显示额度用尽；“本次0次”不代表程序完成了3次。所有阶段共用已有开拓力上限，已有沉浸器独立记账；原货币周常接续不执行新日常或体力计划。说明见[体力计划](docs/power-plan.md)与[历战优先](docs/echo-of-war-plan.md)。

源码 CLI 的 `--read-build-target` 核对「培养目标」入口与到页。`--preview-build-target` 只读观察已打开的培养页或材料详情，将已知材料的可见花萼来源与随包目录精确匹配，显示候选和配置上限。材料缺口、单轮产量与计划次数仍待当前客户端校准。[培养目标与材料预览](docs/power-plan.md#培养目标读取入口)

## 运行条件

- Windows 10 / 11；源码使用Python 3.10及以上；游戏语言为简体中文。
- 游戏客户区16:9，至少960×540，建议1920×1080。已有3840×2160实机验证，其他缩放组合应先检测。
- 使用可截图的前台游戏窗口，运行期间不移动或缩放窗口，不同时操作鼠标键盘。
- 提前处理密码、扫码、验证码、协议和客户端更新；助手只处理已有登录状态下的进入流程。
- 目标副本已解锁，队伍能完成挑战，游戏内自动战斗已解锁；饰品提取需要已有可用差分存档。
- 游戏与助手权限匹配；游戏以管理员运行时，可在设置启用“管理员免重复确认启动”，或使用`Start-AutoHSR-Admin.cmd`进行单次管理员启动。

本项目为非官方社区工具，与游戏开发商、发行商无关联。使用前请自行了解游戏服务条款与自动化工具限制。

## 安装与启动

### 打包版

双击`Start-AutoHSR.cmd`。启动器优先运行`dist/AutoHSR/AutoHSR.exe`，没有EXE才尝试项目虚拟环境中的源码GUI。保留整个打包目录，不要只复制EXE。

打包版配置、日志和报告在 **EXE同目录**，目录必须可写。源码更新不会自动更新EXE；开发时明确运行源码，验证后重新构建。

### 源码版

```powershell
git clone https://github.com/HenryTANG0520/AutoHSR.git
cd AutoHSR
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
.\.venv\Scripts\python.exe -m autohsr
```

`setup.ps1`查找可用的`py`、`python`、`python3`，创建或保留项目内`.venv`，安装`requirements.txt`。指定解释器时：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -PythonPath "C:\path\to\python.exe"
```

执行策略参数只作用于当前PowerShell进程；脚本不安装系统级Python，不修改用户或机器执行策略。直接依赖为RapidOCR/ONNX Runtime、MSS、Pillow；图像处理还使用依赖链中的OpenCV和NumPy。训练工具使用独立环境，日常运行不导入PyTorch或Ultralytics。

### 管理员免重复确认启动

默认未启用。在“设置 → 管理员启动”点击“启用授权”，首次接受Windows管理员确认；若助手已经是管理员进程，则直接登记。操作后重新读取系统任务，状态显示“已启用”才算完成。取消授权或系统拒绝时显示实际结果，不保存游戏配置。

以后从普通`Start-AutoHSR.cmd`、打包EXE或无参数的源码入口启动，自动进入管理员界面，无需每次确认。重复打开会唤起已有的任务界面；正在执行游戏任务时不抢前台。旧`Start-AutoHSR-Admin.cmd`仍是每次请求授权的手动入口，启用新功能后使用普通入口即可。

该功能通过Windows任务计划程序登记`AutoHSR-Admin-v1-…`，仅绑定**当前管理员账户和本软件目录**；无定时、登录或开机触发器，不保存密码。任务只打开默认GUI，不直接运行游戏任务，也不接收调用方追加的游戏参数。普通账户、组织策略限制及任务计划程序不可用时会报明原因。系统授权状态由任务本身决定，不是`config.json`里的布尔开关。

源码与EXE目录分别授权；更新原路径的EXE保留授权，移动目录或更换账户需要在新位置重新启用，移动前可在旧位置“移除授权”。该授权允许固定路径中的AutoHSR以管理员运行，应将程序放在可信、非公共可写的目录中。移除后下次恢复普通启动，不强制关闭已打开的助手。显式`--config`使用其他配置及`--run`等任务CLI不会自动提权；排查入口故障可用`--no-admin-launch`打开设置后刷新、重新启用或移除。

### GUI操作顺序

首页任务卡支持滚轮和底部箭头直接浏览，左右方向键选择卡片，Enter执行卡片上显示的操作。边缘露出的下一张卡先展开再操作；滚出视野的选择不会保留为隐藏的Enter目标。

界面对照本地4.6实机指南复刻，使用星铁实际的指南标记、前三个图标页签、左右挂饰、任务水印、活跃与奖励图标、关闭符号，以及客户端附带的`SDK_SC_Web`字体。前三个图标保持原比例；“记录”和“设置”依次排在它们之后，共用同一页签条。记录采用环轨档案页，设置采用齿轮与菱形轮毂，均由程序绘制；五个图标共用选中底色、灰黑配色、悬停／键盘焦点光晕与名称提示。标题栏与指南外缘采用同一参考中的模糊场景，移除文字及账号区域，遮挡处用邻近颜色插值。黑色圆角书页、活跃徽章、橙色奖励进度与胶囊按钮按参考重绘；任务卡采用原纸面纹样、金色点线与撕口边缘，状态、任务和费用实时绘制；素材来源、裁切和哈希见[UI素材说明](assets/ui/README.md)。沿用AutoZZZ按游戏实际素材制作桌面的做法，继续使用AutoHSR既有Runner。

1. 在“每日实训”核对顶部的日常项目、开拓力和周常安排，点击右下“开始计划”。默认仅执行日常；程序按需启动游戏或复用窗口，从已识别菜单返回后执行。
2. 在“生存索引”左侧浏览六类副本，分类卡沿用游戏的名称、材料类型和顺序，当前浏览分类以深底金色标明。右侧按游戏行式列表展示图标、名称、地点和单次费用。未加入副本时点击“加入计划”，已加入时点击“选用”更换目标；保留能负担的原次数，超出时按本次预算和类别上限收至整次，不提高预算。连一次都无法支付或上限格式有误时显示“调整上限”，点击后定位预算字段、保留原计划。次数滑条与增减按钮也遵守当前有效预算；直接输入的草稿仍按保存或开始时校验。“挑战设置”在列表下方展开预算、支援和次数预设，切换分类或搜索时保持展开；打开后可直接输入预算，Esc收起并返回入口。搜索有内容时Esc先清空搜索；手动填写的下拉菜单先收起，再按Esc返回列表。“读取游戏目录”位于“手动填写”，只有点击该按钮才执行目录采集。
3. 点击任务卡“调整任务”可打开每日任务，使用“开启／关闭”调整安排；未加入的卡片可直接“加入计划”。“周常计划”可选择差分宇宙或货币战争，设置星期、时间与演算局数／对局上限。到期周常在日常完整结束并保存报告后执行，已有目标按原记录核对。需要排查连接时，在“设置 → 游戏连接”核对路径，点击“检测窗口”检查客户区、权限和OCR；“进入游戏”也在此处。检测不执行每日，但会让游戏聚焦。
4. 正常阶段看游戏左下字幕或“运行记录 → 运行日志”。暂停、停止在运行时显示，F9暂停/继续，F10停止。失焦时等待前台，不继续输入。任务卡按钮分别显示本次可用的加入、调整或查看动作。
5. 结束后在任务卡查看状态，左右箭头、鼠标滚轮或键盘左右键可访问全部五项，Enter或“查看结果”打开可滚动详情。底部摘要可点击“详情”展开完整错误、费用和恢复说明。五档实训奖励仅在本次报告`daily_verified=true`后点亮；未核实时以“—”显示，不沿用历史报告点亮。
6. 在“运行记录”查看检测、原始报告，打开截图和运行目录；异常时保留已确认与待核对资源提示。

首页卡片用任务名作为标题，在运行前以“待执行／未加入”显示本次安排；未加入的标签与标题为灰色。副本卡同时显示当前名称、地点、次数和预计消耗。实际执行后的“跳过”保留为结果。计划提前结束时，尚未开始的项目显示“未执行”，点击“查看结果”直接打开对应原因和待核对提示；修改每日计划后恢复安排入口，原报告与总结果仍保留。

任务、摘要和详细记录窗口参照本地4.6提示框，使用居中标题、圆点分隔线、浅色正文、深色底栏与胶囊关闭按钮，右上外角为圆弧。窗口在当前助手中央打开，靠近屏幕边缘时收进当前显示器的可用区域；没有系统标题栏。关闭按钮、Esc和Alt+F4返回原入口，最小化助手时同步隐藏；短提示居中，长记录保留选择、复制和滚动，费用与错误完整保留。较小可用区域仍保留关闭按钮，不抓取暂停／停止控件的输入。

第三个图标为“旷宇纷争”，左侧切换差分宇宙与货币战争，并记住最近的选择。入口沿用游戏插图、布局和右下动作位置；旧截图的等级、赛季倒计时和奖励状态均移除。差分默认显示本次局数、编队、接续方式和通关后选项，点击“开始演算”执行；“操作设置”打开表单，可将本次操作切为“独立领奖”。独立模式显示所选奖励和已打开主页要求，主按钮改为“独立领取红点奖励”；已有月下卡带须另行勾选，模式和卡带均不保存。“查看结果”打开对应完整结果，所选奖励核实与全部红点清空分开呈现。货币战争默认“只读识别当前画面”，观察准备、标准开发、连续运行、积分奖励和单步调试收在“开发工具”，不代表整局已验收。标准开发的新局策略可选“默认／阿格莱雅／希儿”，另可填写记忆开拓者名和选择速通装备方式，仅作用于本次新局／新循环；接续沿用本局或原循环记录，不读取新草稿覆盖。连续运行可设置结束局数上限（0表示直到停止）、积分目标和失败后继续；积分奖励页分别核对、领奖和明确接续，结果与独立验收分列。这些货币运行草稿不保存。切换到设置、结果或运行记录后，同一启动操作移至底栏；始终只有一个可见主按钮。返回每日实训、生存索引或进入“周常计划”后主按钮为“开始计划”；已有未完成原目标时显示“继续周常”或“补存周常结果”。图标悬停或键盘聚焦显示名称。

差分操作设置先聚焦“本次操作”，自动演算和独立领奖分别展示相关字段；货币战争开发工具先聚焦分类栏，运行结果可直接用PageDown翻阅。鼠标“返回”与Esc均回到原入口按钮，保留草稿、文本选择、开发分类和结果滚动位置。下拉菜单或详情窗口先处理自己的Esc；执行期间返回只切换页面，不停止任务或解锁设置。保存时仍校验全部设置；演算字段有误会切回自动演算并定位该字段。

运行栏显示当前步骤与已核实的演算局数；日常结束后立即显示实训结果、实际副本次数和已确认消耗，等待周常时仍保留。任务卡分别打开设置、进行中详情或本次结果，查看单项不会覆盖总结果。独立玩法不重置日常卡片；修改日常计划后卡片回到待执行预览，历史报告继续保留。

计划结果按开始时的任务选择显示。只安排尚未到期的周常时，窗口保留在前台，显示“本次无需执行 · 周常未到期”和原计划时间；进入日常或周常执行阶段才最小化。未安排的日常不再附带零消耗或“实训奖励未核实”，报告中实际出现的消耗、待核对资源、已核实奖励和保存失败仍保留。旧报告缺少任务范围时沿用原展示。

货币战争周常目前执行标准A8-40开发流程与默认购买策略，1～10局为本周上限；积分已满可以不新增对局。只有积分、奖励和成功保存的周常回执全部核实才显示完成。上限耗尽仍显示部分完成；改偏好不会重建同账号同周预算。发现可核对的未完成原目标时，主按钮变为“继续周常”，顶部显示原周、原上限和原日常复用；无需重填当前草稿。接续不执行新的日常，原费用与奖励明确标为“原日常”，不点亮本次实训核实状态。仅剩审计保存时显示“补存周常结果”；本地记录检查不启动游戏、不改写账本。记录损坏时保留原因，不自动接续。完整实机仍未验收，详见[周常计划](docs/weekly-plan.md)。

首页免费任务不再重复显示“0 开拓力”；副本费用明确为“预计”，饰品提取显示“最多”及已有沉浸器优先，非法次数不会生成负数或超范围费用。运行后的副本卡显示报告中的完成次数与实际开拓力、沉浸器；缺失或待核对数据不冒充0，也不继续使用表单预计值。右上角“已用开拓力”表示已确认消耗，初始未运行时隐藏该数值与计时。

时间、次数、预算等输入有误时，直接打开对应页面并选中字段，底栏显示具体原因；窗口缩放后仍可直接替换错误值，保留原本的启动操作。纠正、离开页面或开始运行后，旧定位请求不再抢焦点；已手动选择其他字段时，后续缩放保留该选择。周常页可直接填写预设编队，与独立演算共用。周常未启用时，未填完的时间草稿不影响日常运行；“保存设置”仍检查所有字段。运行失败时，原因、待核对消耗和报告未保存状态优先显示，完整费用与处理建议保留在详情中。

设置在指南书框内打开，一级齿轮页签保持选中。书页内通过文字分类切换游戏连接、每日任务、体力计划、周常计划、运行偏好、识别与等待和管理员启动。选项行左侧为名称，右侧为当前值与操作；长表单只滚动内容区域。点击「返回」或按Esc恢复进入前的页面、启动操作及可用焦点。下拉菜单展开时Esc先收起菜单，指南右上角和窗口标题栏用于退出程序。输入格式、费用和错误原因留在对应字段旁。布局、交互和验收要求见[AutoHSR界面与交互指南](docs/ui-ux-guide.md)。

未加入的任务可点击“加入计划”直接加入当前草稿，不启动或自动保存。只露出边缘的卡片首次点击先完整展开，不修改安排。已加入的委托、实训、邮件和勋礼点击“调整任务”，直接打开“每日任务”并聚焦对应开关；返回保留原卡片位置。副本卡的“更换副本”定位生存索引中当前副本；没有开拓力授权时只提供“查看限制”，不能通过卡片开启。运行中的未执行卡显示“查看安排”，不能加入任务；结果卡仍只打开本次详情。实训合成紧随实训奖励，保留材料数量和适用条件。生存索引只保留副本自己的“加入计划”开关，与设置页同步；其他任务通过首页卡片或“每日任务”设置调整。

设置的展开列表采用游戏中的整行选项、细分隔线和右侧选中圆点；文字侧与圆点侧均可点击。较长列表可滚动，弹层限制在当前显示器工作区内。橙色圆点表示已确认值，键盘移动时保留该圆点，待确认行另有焦点边框。

打开设置或周常计划后，键盘焦点直接进入当前分类的可用选项；下方向键展开选择，Home／End定位展开列表的首末项，Enter确认，Esc取消后再返回原入口。文本输入框和未展开的可编辑下拉框仍用Home／End移动光标。任务卡指定的选项、输入错误字段和正在编辑的内容优先保留；运行期间只聚焦可用的分类导航，不修改或启动计划。

启动时发现游戏程序不存在，会直接打开“游戏连接”并选中路径，显示具体原因。修改后仍需自行点击开始，保存配置仍是独立操作。计划报告保留错误对应字段、已完成日常及消耗；一般运行错误不会根据文字猜测并跳转设置。

勾选框、输入框、下拉选择、次数微调和滑条统一使用指南配色与字体，勾选、禁用及键盘焦点分别可见。差分结果页直接显示完成局数、失败原因和实际存档、领奖、通关后日常结果；后续失败仍保留已完成的演算，未知消耗不写成0。技术字段收在“详细记录”中，该入口保留对应差分报告，不会被之后的其他任务覆盖。

货币战争结果页显示本次识别或开发的具体结果，状态码与截图路径归入“详细记录”，该入口也独立保留对应原始报告。结束时仍待核实的步骤显示“待核实”，不继续显示运行中的动作；未知金币和等级显示“未识别”，与实际读到的0区分。失败原因、报告未保存及下一步保留；点击确认或返回备战页不代表奖励交付完成，更不代表整局通关。

空闲时底栏不显示重复的“准备就绪”；有结果或需要处理的状态时显示一处反馈。查看当前差分／货币完整结果时，同一结果不再在底栏重复。切到其他页面会恢复摘要，新输入错误或其他任务结果仍显示。执行中继续保留当前步骤，详细成本和恢复建议始终可从对应结果或“详情”查看。

周常沿用三月七“运行全部任务时核对周常”的方式，默认每周一04:00后到期，可改星期和北京时间。时间表示**下次点击“开始计划”时是否加入周常**，不会自动唤醒电脑或启动游戏。差分默认执行指定的1～10局周期演算（默认1局）。`--plan --du-until-points` 用周常局数作开局上限，积分已满可零局完成，周期积分领奖单独核对。周计划关闭存档、红点领奖和通关后日常。货币战争周常已接入本周积分核对、限额内标准对局和普通周积分领奖，组合路径仍待实机验收。[周常计划](docs/weekly-plan.md)

助手保持打开时，周常预览会随计划时间和周一04:00刷新点更新。运行中与暂停中的进度保持本次快照；待核对、停止及报告未保存的提示不会被时钟覆盖。跨周后，上一周已完成的提示恢复为本周预览，保留的旧摘要标为“上次计划”，详情标明原游戏周；不会由时间变化启动任务或保存设置。

“设为 1 次”“填满预算”只填表单；运行、检测、仅补领奖使用本次快照，**只有保存设置才写配置**。有未保存修改或尚无有效配置时显示“保存设置”，还原草稿后收起；保存成功在原操作区域显示“已保存”，继续编辑或切页后收起确认。“仅补领奖”只在每日实训、生存索引出现，独立玩法及设置页不显示。运行时收起这些空闲操作并锁定设置，显示当前可用的暂停、停止控制；关闭会先停止并等待后台退出。空闲时关闭未保存草稿，以游戏提示框样式显示“返回修改／不保存退出／保存并退出”；Esc、Alt+F4返回修改，Enter执行当前聚焦的选择。保存校验或写入失败时保留窗口与草稿，小屏仍完整显示提醒和三个选择。

界面文案以任务名、分组和按钮名解释下一步，不重复页首口号、操作教程或开发过程。保留输入范围、预计费用、未验收状态、错误原因、资源恢复与危险操作提示；长结果放进详情，不挤走控制按钮。

放大或最大化助手窗口时，指南、字体、设置行与操作按钮按可用空间等比放大；小窗口保留系统缩放下的可读尺寸。切换比例时保留旧界面及其原字号和样式，新的控件和画面准备好后再替换；最多保留最近两个尺寸的布局，返回相同尺寸时复用控件，只更新变化的画面。还原窗口保留当前页面、输入位置、未保存计划、副本选项与次数范围、浏览结果和运行控制，并重新定位顶部周常入口，不写配置；新布局准备失败时保留原界面。打开下拉菜单或对话框时，先完成当前交互，再调整比例。还原期间仍可能短暂裁切旧布局，尚未达到无闪烁切换。

首页按实机指南的长卡比例排布，右侧露出下一张卡，可直接点击或翻动。日常费用、目标与周常摘要移至顶部，费用在可能截短的副本名之前；周常设置仍一键可达。独立玩法隐藏日常摘要，返回日常计划后恢复。没有结果或错误时收起空摘要栏，必要提示出现时自动展开；五档奖励继续只由已核实结果点亮。

生存索引的104条目录使用对应实机掉落图标或首领徽章。金色花萼按地区、赤色花萼按命途、凝滞虚影按属性分组，使用既有画面核对的21个标题及图标；搜索同时匹配名称、地点和分组。已获开拓力授权且空闲时，即使副本未加入计划也可浏览；分类、搜索、滚动和方向键定位不会改变草稿。点击完整副本行或行内按钮、按Enter才选入计划；未加入时按钮为“加入计划”，同时选择目标并启用副本，已加入时为“选用／已选”。半露出的行先展开，同名副本按地点分别列出。目标、次数、预计费用和预算上限保留在列表下方；取消“加入计划”保留当前草稿目标，费用改为“本次不刷本”，重新勾选可恢复。新副本或旧配置可通过“手动填写”编辑，未核对分组的本地目录列入“其他副本”，不猜测归属或默认选用；输入错误会直接打开相应表单。运行中或未获授权时仍不能选择加入。素材只用于桌面展示，不能证明当前账号已解锁入口，执行仍依赖实时识别与原资源门禁。

未加入计划的副本仍可在空闲且已授权时调整名称、地点、次数、预算和支援选择；这些修改不会自动加入任务。点击“保存设置”会一并保存，下次打开仍保留所选副本及关闭状态。保存时的无效值会定位到可修改字段；运行、检测和仅补领奖仍不保存，也不读取未启用副本的未完成草稿。运行中或未获开拓力授权时继续锁定相关控件。

## 程序架构与识别方式

| 层次 | 如何实现 | 主要代码 |
| --- | --- | --- |
| 窗口/截图 | 按游戏进程找窗口，核对前台、客户区、屏幕边界与DPI，用MSS截取客户区 | [windows.py](autohsr/windows.py) |
| OCR | RapidOCR返回文字、置信度、位置，转为0～1坐标；关键小字、数字局部重读 | [vision.py](autohsr/vision.py)、[models.py](autohsr/models.py) |
| 图标/目标 | OpenCV模板、颜色及几何规则定位图标；差分现场另用本地ONNX模型找方向 | [du_detector.py](autohsr/du_detector.py)、[du_navigation.py](autohsr/du_navigation.py) |
| 页面/流程 | 多锚点确定页面，按已支持的状态转移执行 | [workflows.py](autohsr/workflows.py)、[differential_universe.py](autohsr/differential_universe.py) |
| 动作校验 | 核对操作类型、目标、页面、资源后，经Windows SendInput输入 | [app.py](autohsr/app.py)、[policy.py](autohsr/policy.py) |
| 反馈/证据 | 动作后重截图、等待反馈，保存结果和账单 | [app.py](autohsr/app.py)、[recovery.py](autohsr/recovery.py) |

`Runner`管理任务生命周期、互斥锁、暂停、停止、失焦和报告；`Context`集中封装截图、点击、按键、移动及门禁。GUI以工作线程和事件队列接收结果，不将按钮点击次数作为完成依据。

暂停或失焦使旧输入目标失效，恢复后重新观察。输入前再次检查窗口几何，窗口移动或缩放后不使用旧坐标；持键和拖动在中断时释放。支付已登记而结果未明时保留待核对记录，不重放挑战。

货币战争只读OCR由 [ocr_isolation.py](autohsr/ocr_isolation.py) 放入可终止子进程并设超时；**不是所有模式都启用了OCR子进程隔离**。

## 每日功能如何实现

普通每日按 **委托 → 副本 → 每日实训 → 邮件 → 无名勋礼** 执行已开启项。默认开启前三项，邮件、勋礼默认关闭。约束见 [DAILY_FLOW.md](DAILY_FLOW.md)。

### 启动、登录、返回与月卡

先查找已有游戏窗口，未找到才启动配置的`StarRail.exe`并等待；找到后置于前台，再识别：

- 手机菜单：直接开始任务。
- 已识别的差分、指南、背包等菜单：逐层Esc，最多五次，每次重新识别。
- 已登录进入画面：核实“点击进入”等入口后进入，等待场景或菜单。
- 已拥有月卡补给：核实剩余天数、免费领取提示，无购买流程，领取后核实90星琼，再关闭展示。
- 战斗、未知弹窗、密码/验证码/更新：停止或等待支持状态，不盲目连续Esc。

玩法的“开始游戏”先按玩法菜单识别，不当成账号登录。旧字段`auto_launch`保留兼容，每日始终执行先检查、按需启动。

### 持续委托

`DailyWorkflow.assignments()`识别委托标题、进行中数量、每小时奖励、派遣状态，以按钮颜色区分可领、禁用和未知。领取一次后重新核对奖励收取与持续进行，保留现有委托，不重新派遣或更换材料页。实现：[workflows.py](autohsr/workflows.py)。

### 六类副本与目录

生存索引按分类滚动，每行把**名称、地点、传送/挑战按钮**绑定；不以同名第一项代替指定地点。内置目录采集104个入口；“刷新游戏副本”只采集指南、写本地目录，不开始战斗。

| 分类值 | 分类 | 单次开拓力等价费用 | 普通每日配置次数上限 |
| --- | --- | ---: | ---: |
| `calyx_golden` | 拟造花萼（金） | 10 | 24 |
| `calyx_crimson` | 拟造花萼（赤） | 10 | 24 |
| `stagnant_shadow` | 凝滞虚影 | 30 | 8 |
| `cavern` | 侵蚀隧洞 | 40 | 6 |
| `echo_of_war` | 历战余响 | 30 | 最多3，以游戏本周余量为准 |
| `planar` | 饰品提取 | 40，已有沉浸器可抵一次 | 6 |

这是程序当前分类与配置规则，开战仍核对游戏实际价格、次数和余额。GUI减号、滑条、加号及整数输入设置总次数，预计消耗不得超预算。按游戏单次或批量页面执行，一批最多六次；结算次数须与请求一致，达到总次数即停止。

[dungeons.py](autohsr/dungeons.py)管理类别、费用、目录；[dungeon_workflow.py](autohsr/dungeon_workflow.py)负责行绑定、细读、滚动；[dungeon_ui.py](autohsr/dungeon_ui.py)提供选择器；[workflows.py](autohsr/workflows.py)调整游戏次数并挑战。

旧配置`dungeon_category=auto`按旧名称推断分类，`challenge_count=null`保留按预算刷本，`rounds`表示每批上限；新GUI保存明确分类和总次数。详见 [副本与次数](docs/daily-dungeons.md)。

### 编队、支援、战斗、结算

普通副本按`use_support`借好友，核实列表、角色卡、满员反馈、绿色支援标记后开战。满员时只检查当前卡绑定的提示，有限尝试下一张，不假定点过就借到。

饰品提取按配置预设名走“预设编队”，核实同一行“已启用”和四人完整。开启支援时使用内嵌列表，已有借用若能核实为首选偏好且退出列表后仍在原槽位，可直接复用。[编队实现](autohsr/planar_team.py) · [支援偏好](docs/support-preferences.md)

进入回合战斗后识别自动战斗开关，必要时开启**游戏内自动战斗**；程序不决定每回合技能。饰品首领房核实场景、首领及普攻图标后有限接近、普攻接战；失败则停止，不重新开始挑战。

结算看到成功页面和相符波次，才将本批资源从待核对转为已确认。开战前核对并关闭快捷补充，余额不足停止，不点击资源补充。

### 饰品的两类资源

[planar_resources.py](autohsr/planar_resources.py)分别读取开拓力、沉浸器、次数及付款区图标，核对游戏优先使用已有沉浸器的价格。例如五次、四个沉浸器应为 **4个沉浸器 + 40开拓力**。图标、数额、次数全部对应才开战。

报告独立记两种资源，不把沉浸器写成已花开拓力。仅用已有差分存档，不新建或替换；不合成、兑换沉浸器，不用深度沉浸器快速提取。

### 每日实训与单件合成

先逐项领已完成任务点数，再读取活跃度；**500活跃且五个里程碑均已领取**才令`daily_verified=true`。点击领取或只见500不足以证明全部完成。

活跃不足500且`daily_synthesis=true`时，检查同一卡片是否同时有“使用1次万能合成机”、0/1、+100和“前往”，全部成立才执行：

1. 从任务打开消耗品合成，用零食图标找候选，再OCR核对奇巧零食配方名。
2. 核实数量恰为1、库存可读、两种材料各需1且足够。数字漏读则局部重读，不能确定就不合成。
3. 按账号与04:00重置的游戏日写待核对记录，再点合成。
4. 核实“奇巧零食×1”弹窗，持久化确认已发送状态，只确认一次。
5. 关闭对应奖励展示，核实零食增加1、两种材料各减少1，再返回每日实训页面，领取任务点数及里程碑奖励。

实现：[daily_synthesis.py](autohsr/daily_synthesis.py)。重启可接续原确认或核对结果，不重放配方“合成”；确认已发送而结果不明时停止。材料不足不换物品或购买，也不为此开差分。设置可关闭，“仅补领奖”始终不合成。

2026-10-25实机为零食299→300、材料301→300和397→396，随后500及五档奖励完成；有修复接续，不计一遍无人接管通过。

### 邮件与无名勋礼

[free_rewards.py](autohsr/free_rewards.py)识别图标、页签、按钮颜色和状态，[workflows.py](autohsr/workflows.py)串联：邮件领取后核对物品展示及禁用/已领取；勋礼依次查本周、本期任务、免费等级奖励，核对经验、等级或奖励。

静态购买按钮不代表进入购买弹窗；程序不点购买、解锁付费奖励，真实购买或自选奖励弹窗停止。

## 差分宇宙如何实现

### 开局与成功计数

左侧差分为独立任务，不混用每日预算。默认`periodic`周期演算、3局，可设1～10局；周期难度沿用准备页已选值，不强制V。常规模式代码保留，常规实机验证暂停。

每次新开都走“下载角色 → 预设编队”，按名称选 **哈哈哈哈**，核实同一行启用与四人完整。历史验证队伍为火花、爻光、银狼LV.999、真珠。当前成员以本次编队为准。[预设实现](autohsr/du_team.py)

`DifferentialUniverseWorkflow`分类页面，再分派开局、选项、现场、战斗、领奖、终局。独立成功保留新开局、编队、最终胜利、返回证据；手动干预、修复接续和失败分别记录，不能混入独立数。

### 门、卡片、怪物

`du_target.onnx`找粉门，`du_cards.onnx`找卡片，敌人模型及有限补充模型提供敌人方向；均通过ONNX Runtime CPU运行，再用几何、OCR和图标核对状态。

**粉色不充分证明是门。** 门板、金色长框、眼睛结构区分睡眼门、苏醒门、背面，粉色画笔、广告、旗帜、设备是反例。门/敌人检测框只给方向，不单独授权攻击或F。权重、数据和评估见 [模型说明](assets/models/README.md)。

卡片浮空标题可补充侧面或漏检方向，但交互仍需实时右侧提示及真实F图标。两三张卡的房间每次事件后重看现场；门仍睡着继续处理，只有苏醒门或实时随意门提示支持离开，不用交互次数推断完成。

### 接战、视角与防卡死

新战斗房等进场稳定，保持初始朝向做一次有界直行，不一进场就乱转。接续现场不假定朝向正确，先用粉门恢复定位。攻击圆环与敌人信息条共同核实，或受限流程其他证据成立，才普攻接战；可读弱点用于切换**现有四人**中的接战角色，不更换预设。回合战斗由游戏自动战斗完成。

缺目标优先原地转视角，找到后对正短步走，减少横移。清场苏醒门优先于敌人、广告、可选设备；短暂遮挡只保留有时间、次数上限的接近。

`BackgroundProgress`在约2秒窗口内排除HUD和角色，比较背景特征与光流；证据足够且几乎无位移才判停滞，**不是比较整图动画是否静止**。移动观察器还检查红色三角边界、F提示、攻击圆环、页面切换，命中立即释放持键。

脱困只允许当前流程限定的后退、侧移、短前进，有距离、次数、时间上限；背景正常移动而提示未消失不能触发脱困。超限留证停止，不无限绕圈。红三角阻止向前，不是导航目标。实现：[du_navigation.py](autohsr/du_navigation.py)、[du_tracking.py](autohsr/du_tracking.py)、[differential_universe.py](autohsr/differential_universe.py)。

### 祝福、方程、事件和卡片效果

祝福不固定选第一张。[du_strategy.py](autohsr/du_strategy.py)定位一至三张卡，按顺序比较：

1. 右上用户指定的绿色推荐标记。
2. 游戏预览能完成多少方程、推进多少未完成方程。
3. 发牌员效果、欢愉。
4. 星级、已识别生存效果。

这是本地按序比较规则，不是通用攻略引擎。弃置优先避免使方程失效、减少进度倒退，再比较已有偏好；选中、高亮、确认和结果另行核实。

站点按区域偏好选，确认前读稳定效果预览，避开已识别的死亡伤害全队等危险信标。事件以右侧小星星定位选项，检查碎片花费、负面奇物与损失，倾向已知风险低的选项；花碎片须有可读、足够余额。继续箭头独立识别，不点标题或描述。实现：[du_events.py](autohsr/du_events.py)。

站点卡按**完整指令**解析，把目标张数、等级增量、信标数、奖励数分开。因此`+1/+2/+3`不是三种写死页面，支持的升级语法接受正整数，奖励数不变成点击数。支持升级、转换、复制、删卡、信标及部分进入区域/触发次数条件，未知动词、费用或组合仍停止。实现：[du_card_effects.py](autohsr/du_card_effects.py)。

休整、商店、铸造等先区分必做卡片与可选设备。门醒优先走，不反复开调试台；能选商店/铸造站不等于授权购买/铸造。冒险仅处理已校准的小小哈努提示、挑战和结束状态，不支持全部小游戏。实现：[du_adventure.py](autohsr/du_adventure.py)。

### 可选：存档

`differential_universe_save`默认关。只用空槽，不覆盖旧档，名称从`AutoHSR-1`开始，后续读最大编号加一，如`AutoHSR - 2`。未核实到空槽时放弃保存，单独核实返回，不宣称槽位已满；新状态与旧`skipped_full`历史分开展示。见[保存协议](docs/du-archives.md)及[页面规则](autohsr/du_saves.py)。已有AutoHSR-1的存在、日期、队伍实机核实；**自动键盘命名仍需单独实机验证**，不能用存档存在证明该路径通过。

### 可选：红点领奖

`differential_universe_rewards`默认关。等主页入口连续两次完整、位置稳定后，依红点处理拟合等级、月下奇谭、稳态数组、可能性画廊，再返回复核。

画廊按分类红点进入，再点“奖励进度”；边缘红点指向画面外时向相反方向拖动，核对位置变化。只领已达成档，未来奖励详情不算成功，黄色“新”不算红点。实际领取须有物品展示。月下奇谭可花**已有月下卡带**，先核对单次100与余额，不兑换卡带。中断在已识别奖励页可有限接续，未知红点停止。实现：[du_rewards.py](autohsr/du_rewards.py)。

### 可选：每日首次通关后日常

`differential_universe_daily`默认关。胜利和返回证据保存后，按账号、中国服务器04:00游戏日去重，回外部处理委托、实训、真珠所需浴火钢心饰品、邮件和免费勋礼，再返差分。

开始时按已有体力和沉浸器**冻结次数**，最多六次一批，逐批独立账单。300体力可拆多批，故不同于普通每日单次240的总上限；期间自然恢复不增加计划。资源不足不补。有支付意图或未核对账单不重放；只有免费领奖失败可依记录有限补领。

`differential_universe_daily_from`指定开始游戏日，凌晨04:00前仍属前一天。已有分段接续验证，完整插入路径待新游戏日独立验收。实现：[du_daily.py](autohsr/du_daily.py)。完整说明见 [差分操作](docs/differential-universe.md)、[逐局证据](docs/du-validation.md)。

## 货币战争实验如何实现

货币战争继续开发标准博弈 A8 财富造物主 40。此前的十场独立验收目标已于 2026-10-26 终止。对局通过独立页面或显式命令启动，报告与每日预算独立。

| 能力 | 机制与验证 |
| --- | --- |
| 只读识别 | 多锚点区分入口、主页、攻略、教学、备战、战斗、结果等；冲突或未知保留unknown，不输入 |
| 受限建议 | 策略带来源、版本、范围，白名单条件给建议，不自动变成交易 |
| 前台3→1换位 | 当前格位拖动，动作前后留证，显式单次实验 |
| 备战部署 | 核对前/后台适配、空槽，验证头像、原格清空、人数、金币 |
| 经验升级 | 指定等级后逐笔核对4金币与4经验，未知余额不当可支付 |
| 补给与物品 | 选已校准角色/装备组合，核对高亮；晶矿、武装箱、邀请函只处理支持内容 |
| 整理与装备 | 核对同名备战副本及金额后出售，有限穿戴电池、防御装备、蓄能帆，复核库存和装备 |
| 节点/连续流程 | 串联支持的出战、胜利、结算、地图、投资、终局；新开超频A0为单独显式入口 |
| 样本回放 | PNG、OCR、哈希和`.sample.json`，离线回放或独立重OCR，不访问游戏 |

标准节点继续挑战后若出现「强敌来袭」，只有核实实际到达相邻首领的备战页或商店，才记为节点推进。介绍和到达分开留档，已通过离线回放。[货币开发记录](docs/currency-wars-development.md)

`currency_wars_*.py`按页面、阵容、位置、经济、商店、装备、奖励、节点、流程拆分。商店评分/购买有离线原型，连续流程主要收起商店，不代表完整运营实机通过。开发对局有SSS，但含人工和修复接续，**无完整独立自动整局证据**。见 [开发记录](CURRENCY_WARS.md)、[攻略整理](CURRENCY_WARS_GUIDE.md)。

标准博弈优先使用离线策略，可选大模型 API 辅助。独立离线与 API 命令提供只读原型。标准流程的阵容采集、购买、经验、满员交换、逐笔刷新、节点推进与开发结算已接入并有离线回归，完整独立整局仍待实机验收。[策略调研与双路线方案](docs/currency-wars-strategy-research.md) · [验收与问题记录](docs/currency-wars-validation.md)

`--currency-wars-check`会将`strategy_snapshot`、`strategy_candidates`和`strategy_decision`写入报告，模式、余额或阵容不明时要求补充观察，不因此开启输入或调用API。

同一入口可只读核对遭遇双卡。`encounter` 分列卡名、难度、奖励预览、刷新余数、选中和确认控件状态。识别不完整时保留未知，接续与实际交付仍待验证。[遭遇证据与边界](docs/currency-wars-development.md#2026-11-06-遭遇双卡只读观察)

货币战争页另有“启动准备：进入游戏（不开局）”，CLI为`python -m autohsr --currency-wars-prepare`。它先检查并按需启动游戏，只点击已核实的“点击进入”、已有免费登录补给和关闭提示；从已核实大世界打开手机菜单，已有货币战争页面则保留。密码、验证、协议、下载和未知转换停止，不创建对局、不消费局内金币或每日体力。准备完成以`game_ready=true`记录；整局仍未完成，所以报告保持partial、CLI退出码1。当前实机是分段进入、领奖与打开手机菜单，尚未一遍覆盖未启动至最终入口。

“指南定位：标准模式（不开局）”和CLI `python -m autohsr --currency-wars-locate`在准备后继续打开手机指南、玩法页签及货币战争详情，再进入玩法主页和模式选择。使用右侧“零和博弈/晋升等级/奖励预览”核对详情，左侧分类名称不代替选中证明；识别按钮装饰引号，不把“积分线已更新”信息横幅当按钮。每步先落盘pending，看到目标页才记verified；未知保留截图和回放、不反复点击。专用输入会重新核对当前画面与输入代次，普通只读及旧超频实验不能借用。到标准模式配置页以`entry_ready`记录，尚不提交“进入标准博弈”或“开始对局”；实际验证进度见[验收记录](docs/currency-wars-validation.md)。

“配置标准A8-40（不开局）”和 CLI `python -m autohsr --currency-wars-configure` 打开标准职级列表，默认目标为 40。独立配置可显式指定本次档位，例如 `python -m autohsr --currency-wars-configure --currency-wealth 48`。参数范围为 1～50，执行只选择当前可见且朝目标靠近的行。完整页面锚点、数字、蓝色背景和白色字形共同确认已选档位。每步重新截图核验，验证、协议或更新提示会阻止核实。整图漏读时，隔离 OCR 对原图和二值图的局部数字一致后才补读，再核对高亮。历史实机分段核实到 40，其余档位已有离线回归。独立配置在开局前结束，档位覆盖不写入设置。

独立 CLI `python -m autohsr --currency-wars-configure-overclock` 可在已打开的模式页选择超频博弈，核对同账号的两张新画面后停在模式页。同一运行记录目录下有旧选择待核对时，新进程停止在点击前。已打开的超频模式与 A0 黑铁难度页仍可只读核实，其他档位仅报告识别状态。标准开局、循环和周常仍走各自的 A8-40 入口。当前为历史脱敏布局与假窗口验证。[超频配置与证据](docs/currency-wars-development.md#2026-11-06-超频选择与回执门禁)

客户端 `4.6.0` 可用独立 CLI `python -m autohsr --currency-wars-open-overclock-a0` 从已选超频的模式页点击一次「进入超频博弈」。成功条件为同账号连续两张 A0 黑铁难度页，已在 A0 时零点击核实。输入仅限打开难度页，非 A0 或冲突反馈停在当前页并保留待核对记录。本步骤已按历史脱敏 OCR 做离线验证，连续实机回执待采集。[入口与回执](docs/currency-wars-development.md#2026-11-06-超频-a0-难度页单步)

“标准开发：新开A8-40”与CLI `python -m autohsr --currency-wars-standard`在核实配置后提交一次新对局，记录首领预览、位面转换与当前局面。`--resume-active-currency`或“接续已记录A8-40开发局”只接续已核实开始且上步无待核对动作的记录。`runs/currency-standard-session.json`原子保存对局标识和逐步pending/verified/unknown；Context输入前回读核对已落盘意图、动作、输入代次和新鲜画面。旧只读、准备及超频入口不能发送标准开局；已有对局记录阻止再次开局。已实机验证开局、环境选择确认及开场掉落领取，停在1-1备战；此后新增的标准采集、购买、经验、合法满员交换和节点推进通过离线回归，未作为完整实机整局验收；开发接续不计独立验收。

标准环境候选按卡片完整正文解析：角色张数/星级/费用、投资刷新次数、额外金币分别记录，支持已核实语法中的数字变化。当前覆盖战力飙升、银·金·彩、蓝海和既有人身意外险的效果类别；未知正文或额外条件不默认第一项，不自动刷新。`initial-strength-v1`是未实战校准的工程评分，偏向初战高星角色及成长，不代表胜率或最优策略。选择后必须核对唯一高亮边框与启用的确认按钮，再确认进入1-1。标准掉落复用已校准晶矿实体检测与空备战位检查，连续两次核对晶矿消失、节点/生命与余额条件后继续，不把拾取光环当作已领取。

标准阵容采集扫描前台4格、已校准后台6格和备战9格，部署人数与角色槽必须一致；不确定纹理不当作空位，带“开启”的物品不当角色。逐张打开持有角色面板，费用来自右上角独立字段（漏读时由OCR子进程原图/二值图双读），星级来自顶部星核分割；出售返还、费用和星级不混用。记录名称、羁绊、适配、已核实空装备槽及14类已支持的非空装备；未识别装备保持未知，推荐与配方通过当前角色面板读取。相同节点及头像对应全部持有格后才设置`roster_complete`，角色增减也使旧完整标记失效；新运行、输入代次使采集失效。已核实的部署只迁移对应身份及头像，其他改变的槽重新查看。此前已实机采集1-1五张卡；新增仓库、推荐配方与穿戴路径仅通过离线验证。

标准会话在接续及每次输入前核对当前UID与本局指纹，原UID不进入会话结构或模型局面。旧记录只可从原始A8-40入口的哈希校验截图补建绑定，账号不符、缺少来源或文件越界则停止。客户端版本从当前游戏进程路径旁的`config.ini/game_version`读取；兼容节名大小写、UTF-8及带BOM的UTF-16，拒绝重复或不完整字段，不使用EXE的Unity引擎版本。4.6安装版本只匹配已转录的基础经济规则，不替旧4.4路线包扩范围。

标准商店有独立入口契约：本局、账号、版本、完整阵容及六格后台均核实后才打开，并拒绝已识别的超频标记。开店反馈核对商店、节点、金币与等级；生命值被面板遮挡时保持不可见，若仍可见则必须一致。仅这种无消耗界面转换可在接续时通过观察核对，保留原unknown及核对来源，不重放点击、不用于交易对账。OCR子进程对缺失售价和名字使用一致的局部变体，已读数字不重写；实际售价按0～99可见字段记录，星级/费用档位仍独立且不从售价推断，旧超频购买范围仍只允许1～5。已实现逐笔角色购买、经验成长及三种策略的已有角色补空位偏好，输入前落盘意图、支付后重新采集并核对；这些新增交易路径尚未实机验收。满员交换仅覆盖已支持的合法阵容。逐笔刷新读取当前费用并核对两帧扣款、报价变化和备战席，已核实收据约束每节点最多六次、累计十二金币；未知结果不重放。出售与装备路线尚未完整适配，不代表完整复现上游。固定参考源码、GPL许可和适配范围见[March7thAssistant来源说明](assets/upstream/March7thAssistant/README.md)。

标准备战出售先独立核实角色身份，核对实际金币返还、来源格清空及其余18格不变；保护核心、携装和未核实角色，未接入直接出售在场角色。标准装备阶段按已读推荐、配方和仓库选择已支持装备；仓库少一件只进入“核验角色装备”，实际角色穿戴内容与返回备战页均核实后才显示“装备已核实”。不符与未知结果保留，不能当作节点或整局完成；消耗品与未知装备不自动使用。来源见[上游装备清单](assets/upstream/March7thAssistant/equipment/sources.json)，这些新增路径仍未实机验收。

标准武装箱及补给已接入逐项选择、确认与交付核对，支持已校准的装备、现金和四／五组角色装备补给。返回备战页、仓库变化只证明对应转换；有角色的补给还须重新核实所选角色新增或升星、其余阵容未变，才能显示“奖励交付已核实”。未完成时分别显示“补给角色待核实”或“补给角色不符”，原始动作与交付记录保留。邀请函、补给刷新、投资与特殊效果尚未完整适配，新增交付路径仅通过离线验证。

标准备战新增`owned-deployment-v1`离线基线：先查看本节点商店，再核实“收起”及原生命/金币/等级，记录已查看节点以避免反复开店。有空位时枚举已有不同角色及合法前后台组合，比较已读星级、费用、羁绊重合及前后台分配；先部署前台，不把重复名字当作两名羁绊成员，也不为了空位先购买。评分尚未实战校准，不等于胜率或已激活羁绊。每次专用拖动前重新推导计划、回读落盘目标、核对账号及新鲜画面；复用拖动中暂停/失焦释放机制。连续两次核实来源格清空、目标头像出现、人数加一、金币/生命/等级不变后迁移采集，未知反馈不重拖；标准节点出战、节点推进及开发结算已接入并通过离线回归，完整实机路径尚未验收。满员交换在一次拖动后分别核实两边角色面板及返回，界面先显示“核验换人角色”，两边身份与返回均确认后才显示“换人已核实”。开发局胜利与结算均核实后单独保留该结果，仍不计独立验收。

独立离线/API决策命令：

```powershell
# 读取本地统一局面；默认为离线，不访问游戏。
.\.venv\Scripts\python.exe -m autohsr.currency_wars_planner --state 局面.json
# 也可使用正常只读采集保存的.sample.json，不把旧图当成当前画面。
.\.venv\Scripts\python.exe -m autohsr.currency_wars_planner --sample 路径\画面.sample.json
# 显式选择API辅助；API密钥从AUTOHSR_LLM_API_KEY环境变量读取。
.\.venv\Scripts\python.exe -m autohsr.currency_wars_planner --state 局面.json --provider hybrid --base-url https://your-provider.example/v1 --model your-model
```

统一局面包含事实证据及输入代次，不能把普通截图OCR清单直接当作完整阵容；当前真实画面适配尚不补造这些字段。`--routes`可读取单独的版本化路线文件，不接受旧4.4建议JSON的格式；尚未发布当前标准模式策略包。API缺配置、超时、限流或回答无效时回退；只发送结构化游戏事实，默认无图片，不发送本地证据路径。参数`--token-limit-field max_completion_tokens`可选择该输出限制字段，默认`max_tokens`；供应商兼容性须另行验证。所有输出`executable=false`，GUI尚未开放新引擎的实战运行。

## 日志、报告与恢复

### BetterGI风格前台字幕

[overlay.py](autohsr/overlay.py)接收GUI同源的日志、任务、暂停、失焦事件，用独立进程、有界队列送给 [overlay_native.py](autohsr/overlay_native.py)。后者用原生分层窗口、Pillow绘制透明状态栏、时间、等级、滚动文字，随游戏客户区缩放。

窗口不激活、不抢焦点、鼠标穿透；失焦、最小化隐藏。Windows截图排除标记防止污染MSS/OCR；排除不支持或绘制失败则隐藏，文件日志继续。队列拥塞只影响显示，不阻塞任务。`overlay_logs=false`可关。样式参考BetterGI，非逐像素复刻，来源见 [素材说明](assets/ATTRIBUTION.md)。

### 消耗账单与仅补领奖

普通每日预算默认每次240，**不是跨运行的账号每日额度**。挑战前写`runs/battle-session.json`支付意图，成功结算才确认，沉浸器独立字段；写账失败不开始，损坏或结果不明停止。

上次支付已核实但刷本未完整结束时，GUI默认取消新增预算，CLI需显式传入`--new-battle-run`。开拓力或沉浸器仍待核对时，日常、计划中的日常和差分通关后刷本均在挑战准备前停止，保留原支付记录。主账本缺失时，检查历史运行报告，差分另检查同账号批次自身的报告。[每日流程](DAILY_FLOW.md)

“仅补领奖”只验证、领取实训，不刷、不合成、不处理附加项、不改配置、不清原账单。会尝试返回已识别主界面，未知战斗或弹窗停止。**不能用它重试待核对合成**，后者由普通每日专用记录处理。

[storage.py](autohsr/storage.py)原子替换配置、报告、账单；短暂Windows占用只有限重试文件替换，不重发游戏动作。

| 本地文件 | 内容 |
| --- | --- |
| `config.json` | 显式保存配置，源码与EXE独立位置 |
| `dungeons.local.json` | 刷新后的本地目录，优先内置目录 |
| `runs/<时间戳>/run.log`、`report.json` | 本次日志、验证状态、消耗、错误、证据索引 |
| 同目录PNG、TXT | 关键画面及OCR |
| `runs/battle-session.json` | 普通刷本支付记录 |
| `runs/daily-synthesis/` | 账号/游戏日单件合成记录 |
| `runs/du-daily/` | 通关后日常去重、冻结计划和批次账单 |
| 差分运行证据账本 | 动作、选择原因、编队、胜利、返回、独立计数 |
| `check_*`目录 | 窗口检测结果 |

`success`为请求条件均已验证，`partial`为部分完成或未核实，`failed/stopped`为失败/停止。`daily_verified`独立保留实训结论，附加任务失败不能抹掉已验证每日；差分胜利与随后领奖也分开记录。

## 命令行

`--run`执行配置中开启的所有每日项；`--plan`额外检查已启用且到期的周常。只测单项需明确测试配置。以下覆盖不自动保存。

```powershell
# 检测窗口、客户端版本和OCR，不执行任务，但会聚焦游戏
.\.venv\Scripts\python.exe -m autohsr --check
# 只启动
.\.venv\Scripts\python.exe -m autohsr --launch
# 已打开差分主页：只领拟合／稳态／画廊已有奖励，不开始演算
.\.venv\Scripts\python.exe -m autohsr --du-rewards-only
# 按配置执行每日
.\.venv\Scripts\python.exe -m autohsr --run
# 日常刷本按当前实训需求借用支援
.\.venv\Scripts\python.exe -m autohsr --run --support-daily-only
# 按配置执行日常与到期周常，不登记定时任务
.\.venv\Scripts\python.exe -m autohsr --plan
# 单轮花萼参数；其他任务开关仍取配置
.\.venv\Scripts\python.exe -m autohsr --run --category calyx_golden --target "回忆之蕾" --location "绘世学院" --count 1 --stamina 10 --rounds 1
# 只补实训奖励
.\.venv\Scripts\python.exe -m autohsr --run --reward-only
# 只采集目录
.\.venv\Scripts\python.exe -m autohsr --scan-dungeons
# 新开一局周期，其他可选开关取配置
.\.venv\Scripts\python.exe -m autohsr --differential-universe --du-mode periodic --du-team "哈哈哈哈" --du-runs 1
# 接续用户已开启并选难度V的当前周期局
.\.venv\Scripts\python.exe -m autohsr --differential-universe --resume-active-du --du-periodic-rank 5 --du-runs 1
# 货币战争只读，无游戏输入
.\.venv\Scripts\python.exe -m autohsr --currency-wars-check
# 离线回放，无游戏访问；加--replay-ocr可重OCR
.\.venv\Scripts\python.exe -m autohsr --currency-wars-replay "路径\样本.sample.json"
# 离线单测
.\.venv\Scripts\python.exe -m autohsr --self-test
# 查询、启用、移除本目录的管理员启动授权；不访问游戏
.\.venv\Scripts\python.exe -m autohsr --admin-launch status
.\.venv\Scripts\python.exe -m autohsr --admin-launch enable
.\.venv\Scripts\python.exe -m autohsr --admin-launch disable
# 跳过管理员入口，打开设置排查；打包版也可使用此参数
.\.venv\Scripts\python.exe -m autohsr --no-admin-launch
```

`--config`指定配置，`--game-path`覆盖路径；`--target/--location/--category/--count/--stamina/--rounds`覆盖副本。差分用`--du-save/--du-rewards/--du-daily`开启可选项，`--du-daily-from YYYY-MM-DD`限起始日，仅用于差分入口。完整参数看`python -m autohsr --help`。

`--check`的`game_client`字段区分版本已核实与未知，只包含游戏版本、来源类型及哈希，不输出安装路径；该命令的原有完整OCR与截图路径仍供本地排查，不是公开脱敏报告。

打包EXE无终端控制台，游戏任务CLI后读EXE同目录`runs/`；终端JSON用源码命令。管理员授权CLI不创建游戏报告，打包版在设置里“刷新状态”核实结果。通常退出码0成功、1未完整成功、2参数或配置错，键盘中断130。

2026-11-05 的已验证正式包对应代码`7f4e4d7`，包含差分保存协议、独立领奖及货币循环／积分／领奖 GUI。该批通过 2355 项完整回归、268 项相关回归，核对了包内 451 份资源与 239 份原用户文件。近期刷本门禁、晶矿连续领取、投资赠箱、差分确认反馈、混沌选层反馈与校准工具为源码交付。本地管理员助手仍开启，正式包待其退出后更新。真实整局、领奖及保存仍待验收。[验证记录](VALIDATION.md)

辅助`python -m autohsr.audio`默认只读播放设备。明确要求静音时用`--mute --record-dir <新目录>`保存原状态、静音、复读核验；不启动游戏、不改麦克风、不解除静音，也不是默认每日步骤。

## 操作边界

默认仅用已有开拓力及支持的已有沉浸器，不用燃料、星琼、后备领取或购买补资源，不抽卡、充值、角色/光锥/遗器养成。

例外各自限定为：明确实训的一个奇巧零食、差分已核实事件碎片与月下卡带、货币战争显式实验局内交易。它们不开放通用商店、合成、补资源；选中商店/铸造区域也不授权购买或铸造。

完成后保留游戏，**无自动退出游戏功能**。断线重连是否继续取决于能否返回已支持页面，不承诺处理全部断线或客户端更新。

### 构建

先完成源码安装并确保项目环境已有PyInstaller。脚本**不自动安装**缺失依赖，需安装时显式执行：

```powershell
.\.venv\Scripts\python.exe -m pip install pyinstaller
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build.ps1
```

关闭空闲旧助手后构建。先到`build/package-...`暂存，复制依赖、最后发布EXE；配置和运行记录原位保留并备份到`build/userdata-时间戳`。输出带OCR依赖、模板、ONNX、许可证、说明，资源在`_internal/assets/`。

源码版本以 Git 提交为准。构建已结束且 `dist/AutoHSR` 正式包已核对后，可清理 `build/AutoHSR` 的 PyInstaller 中间产物和无占用的 `build/package-*`。`build/userdata-*` 存放配置与运行记录备份，按用户数据保留。

## 常见问题

| 现象 | 排查 |
| --- | --- |
| 改源码行为没变 | 启动器优先EXE，明确用源码或重建 |
| 在其他菜单 | 每日从已识别菜单逐层返回，未知弹窗先核对 |
| 失焦后停住 | 等待前台，将游戏切回，不并发另一套控制 |
| 输入被拒绝 | 检查权限匹配；设置启用管理员免重复确认并正常重开，或使用管理员启动器 |
| 管理员入口失效 | 用`--no-admin-launch`打开设置刷新、重新启用或移除；移动前先移除旧目录授权 |
| 黑屏/尺寸不对 | 检查窗口模式、HDR/滤镜、尺寸和屏幕边界 |
| 有体力仍停止 | 查次数、预算、实际价格、周余量、待核对账单，不盲目重建预算 |
| 500却未成功 | 检查五档及其他开启任务，各项验证独立 |
| 合成停在确认/奖励 | 保留记录，由普通每日核对，不删账重复合成 |
| 字幕不显示 | 查开关/日志；失焦、最小化、排除不支持时隐藏 |
| 新数字/场景漏识别 | 保留PNG/OCR/日志，补布局和语法回归，不只降全局阈值 |

反馈附版本、分辨率、缩放、步骤和脱敏日志，公开截图前检查UID、昵称、好友信息。
