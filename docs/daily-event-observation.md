## 读数接口

[识别模块](../autohsr/daily_event_pages.py) 的 `phone_journey_event_entry(scene, client_version='4.6.0')` 返回原始手机图标文字 Token。图标须处于完整手机布局的对应位置，同排合成和上方商店均有正向读数。版本不符、遮挡、移位或重复文字时返回 `None`。

`read_gift_of_odyssey(scene, client_version='4.6.0')` 核对右侧活动标题、活动说明、左上活动札记及卡片分隔线，再分别读取七个卡位。每个可领日需要本格的完整「领取」文字与浅色按钮一致。每个已领日需要本格的完整「已领取」文字与暗态一致。低清 OCR 对两个栏目文字的实际错字仅作为其固定位置的辅助读数。结果按 `claimable_days`、`claimed_days` 和 `unknown_days` 分列，空的可领列表只能表示本帧没有核实到可领卡。整个页面不明时返回 `None`。[正反例](../autohsr/tests/test_daily_event_pages.py)

当前证据只覆盖一次公开录屏的已解锁与已领取状态。尚需用本机同账号、同版本连续画面核实入口到页、未解锁卡、原生输入前后的来源和逐笔到账。邻页礼券、其他签到标题及双倍活动继续各自核实。

## 独立导航

在任务流的可视编辑中选择「切换到游戏页面 → 巡星之礼」。手机点击使用双帧一致的「旅情事记」图标文字。进入活动后，左栏必须找到唯一巡星之礼横幅，且顶部同时核实奖励指南徽章和文字条。横幅位置随列表滚动变化。已在巡星之礼时直接核实到页，找不到横幅时保留当前画面。流程不点奖励卡、不会自动滚动或重发原点击。

源客户端固定校准到 4.6.0。发送前、到页和提交报告均重核窗口、账号、输入代次、安装来源及版本。P5 的 108.0 秒取三个最小模板，122.5 秒和 90.0 秒是同次录屏不同列表位置的复放，127.9 秒是奖励叠层反例。到页与两次导航发送使用正式任务流 CLI 和假窗口核对。[素材裁剪与摘要](../assets/ATTRIBUTION.md#2026-11-07-巡星之礼活动导航)

## 巡星之礼单日提交

`--daily-event-claim DAY` 是独立命令。已登录的简中 4.6.0 窗口须在前台，且已打开巡星之礼。明确指定第 3 至 7 天中的一天，两张连续画面均须核实同一账号、日卡和可领取按钮。第 1、2 天及其他活动沿用只读观察。

若当前已打开手机菜单或活动列表，可显式附加 `--navigate-daily-event`。例如 `python -m autohsr --daily-event-claim 4 --navigate-daily-event` 从手机核对「旅情事记」，再从活动列表核对巡星之礼横幅。已经在巡星之礼时直接核实到页。导航最多执行这两次点击。到页后重新采集日卡，并再次比对同一账号、窗口、输入代次与安装来源。报告的 `workflow_navigation` 与 `daily_event_claim` 分别记录到页和领取。此选项可与回页观察组合。

程序先保存排他领取意图，最多发送一次当前日卡的点击，并在同账号两帧中核对符合该日数量的奖励弹窗。报告分别记录 `submission` 和 `popup`。默认在核对弹窗后结束，报告 `partial`。失焦、停止、错页、缺账号或落盘异常会中断相应阶段，已有待核对意图保留，重复运行无法重发。

从同一次领取继续核对回页时，可在命令中附加 `--observe-daily-event-return`。终端提示出现后，保持游戏前台并手动关闭当前物品弹窗。程序在原八秒证据窗口内额外读取至多八次，连续核对相同弹窗或返回日卡。指定日的已领取状态须连续两帧一致，其他卡片的已领取状态及此前可领的按钮须保持原样。通过后排他保存同卡回执，`state` 为 `verified`，命令返回 0。等待超时、画面冲突或回执不完整时保留 `pending`，当前运行无法重新领取。回执核实的是弹窗展示票数与日卡变化，账户票券余额另待核对。

单日运行报告在本次目录排他发布，已有同名报告保持原样。若同日卡回执原件已保存、运行报告因争用未发布，命令返回 1，分别报告 `status=partial`、`report_saved=false` 和 `daily_event_claim.state=verified`。同日卡重跑仍受原意图拦截。报告目录需支持本地硬链接，已用 NTFS 验证。

桌面从「设置 → 工具 → 日常页面核对」选择「本次巡星之礼领取」。先手动打开活动页，明确选择第 3 至 7 天中的一天，再点底栏「提交本次巡星之礼领取」。提交后手动切回已登录的游戏前台，F10 可停止。原有「巡星之礼」选项只核对当前页面，日常和任务流沿用各自原入口。

如需核对关闭后的同卡状态，请在提交前勾选「同时核对关闭弹窗后的同一卡片」并阅读选项旁的说明。运行中按说明在弹窗稳定后尽快手动关闭并留在活动页。桌面回执分别显示输入、奖励弹窗、关闭后同卡和账户余额。已有领取记录沿用同一账本门禁，完成后再次提交前须重新选日卡。桌面使用隐藏 Tk 和假窗口验证，当前游戏中的人工关闭时机与实际到账仍待核对。

## 奖励指南

任务流的 `workflow_open_page` 可选择 `target: reward_guide`。从手机打开旅情事记，或直接从已核实的活动列表及巡星之礼进入。活动页必须有独立侧栏证据，再核对顶栏徽章与「奖励指南」文字。只有指南的「旅程热点」布局和内容通过同账号双帧后才确认到页，安装配置保持只读锁直到报告发布。已在目标页时零输入。该步骤不会点活动行的「前往」、滚动或领取奖励。

`--reward-guide-stitch PNG [PNG …] --reward-guide-output NEW_PNG` 支持将 1–3 张用户自行裁好的本地内容 PNG 按从上到下的顺序拼接。请裁去固定标题、滚动条和个人信息，并保留相邻裁片的重复内容。程序拒绝反向、重复、无重叠或接缝歧义，成功时只创建新文件并回报尺寸和重叠行数。输出目录须支持硬链接，NTFS 已验证。另可用独立命令把明确选择的本地 PNG 发往已保存的加密 SMTP 配置。游戏内滚动采集、裁片账号来源、内容完整性和实际邮件送达待验证。[活动日历附件](notifications.md#活动日历-smtp-附件)

桌面在「设置 → 工具 → 截图与识别」选择「本地奖励指南拼接」。添加 1～3 张 PNG，用编号列表核对从上到下的顺序，可上移、下移或移除。选定新的本地 PNG 位置，再按底栏「拼接并导出奖励指南」。预览和排序只更新列表，底栏调用与 CLI 相同的排他导出。成功时显示拼图尺寸和接缝重叠行数。[隐藏桌面回归](../tools/screenshot_ui_smoke.py)

公开 4.6 活动实录 P5 在 232.8 至 234.6 秒显示独立指南页，前后为活动列表。234.6 秒鼠标停在首行「前往」，随后回到活动页并切到星际幻宠乐园。实际 Esc 的反馈仍待单独取证。固定三月七的活动日历提醒会从奖励指南采集数帧，拼接后发送图片。[公开实录](https://www.bilibili.com/video/BV1JZaV6XEH3/?p=5&t=232) · [三月七活动提醒](https://github.com/moesnow/March7thAssistant/blob/7cf6c6bed474539485d3b1504077ac352866829f/tasks/activity/journey_highlights_notification.py)

### 可见列表与内容框

`reward_guide_viewport` 在已核实的 4.6「旅程热点」页上继续核对「进行中」标题和同一橙色分组栏，返回原分辨率的内容框和可见分组。640×360 参考框为 `[126,114,468,315]`，保留活动缩略图、名称和剩余时间，避开固定标题、右侧奖励数及「前往」、底部信息。[识别实现](../autohsr/reward_guide_viewport.py) · [素材来源](../assets/ATTRIBUTION.md#2026-11-07-奖励指南旅程热点)

已打开该页时，运行 `python -m autohsr --screen-test`，或在桌面「设置 → 工具 → 日常页面核对 → 当前页面」核对。只有同一窗口、账号和安装来源的连续双帧都读到相同分组及内容框，匿名回执才附带 `screen_test.reward_guide`。`visible_section` 为 `ongoing`，`content_box` 按左、上、右、下记录原图像素，`frame_size` 给出原图宽、高。可在截图工具中按对应尺寸选择此范围。分组或框待核对时，旧回执仍可报告已确认的奖励指南页名。

需要保存当前列表时，先手动打开奖励指南的「旅程热点」，让游戏保持前台，再显式选择新的本地 PNG 目标。

```powershell
python -m autohsr --reward-guide-capture calendar.png
```

此命令可附带 `--config` 和 `--game-path`。同窗同账号双帧核实后，先保存匿名观察报告，再在客户端安装读锁下复核并排他发布后一帧的内容裁片。输出目录须支持硬链接，原有目标保留。命令回执只包含状态、可见分组、PNG 尺寸及零输入标记。成功返回 0，核对或发布失败返回 1，用法错误返回 2，停止返回 130。真实前台校准仍待验收。[离线回归](../autohsr/tests/test_reward_guide_capture.py)

桌面在「设置 → 工具 → 截图与识别」的「本次操作」选「奖励指南单屏导出」。用「选择 PNG 位置」选一个新的本地文件，再按底栏「导出奖励指南单屏」，随后手动切回已打开「旅程热点」的游戏前台。文件选择只记录本次目标，导出完成后清空该选择并显示匿名结果。导出操作止于本地 PNG，图片发送仍从通知工具单独开始。

接通只读位移前，需要同一 4.6.0 窗口、账号和输入代次的一段连续原分辨率画面，保留完整右外缘。滚动前后各有两张稳态帧。固定页签、横幅与列表边界保持在原处，独立滑块在同一轨道内移动，至少两处活动图文的纵向位移一致、方向与滑块相反，且有唯一、足够长的内容重叠。还需核实「进行中」在实际滚动时是否跟随内容。顶部和底部需另取真实到端与反向返回证据。滑块缺失、接缝歧义、只有计时变化、退场或错页时，位置保留未知。当前只接通单屏读数。[视野识别](../autohsr/reward_guide_viewport.py)

实机取证可在一次零消耗导航内完成。进入「旅程热点」后先手动向上到候选顶部，再滚一格并等画面稳定。向下分段保留相邻重叠，至候选底部后再向下滚一格，最后反向一格核实能离开底端。画面静止时保留未知。随后单击「常时传略」一次，取左栏选中态和同帧独立内容锚点，再切回「旅程热点」。每个停点保留两张稳态全客户区原帧、输入区域和方向。保留一张普通活动页作反例。单屏导出已裁去固定标题与右缘，取证需用原分辨率整帧。
