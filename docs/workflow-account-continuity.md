# 任务流程的账号连续性

更新：2026-10-30。此项接通[任务树后端](task-workflows.md)的跨步骤账号约束，尚未实机验收，不表示完整多账号配置切换、自动登录或全部玩法已经支持。新增账号检查只使用虚构UID、假窗口／OCR和本地临时文件；未访问当前真实账号、Player.log／缓存或安装目录，未新增游戏截图，也没有操作游戏、消耗资源或构建EXE。

## 当前行为

日常、差分与CW自己的账本指纹格式不同。流程使用[现有CW严格UID解析](../autohsr/currency_wars_identity.py)形成独立的本次绑定，不直接比较24位和64位旧字段，也不迁移或覆盖它们。UID仍须位于原生已知区域，完整8～10位ASCII数字、可信OCR及唯一候选共同成立，置信度至少0.85；重复、部分、低置信度或冲突不会取第一项。

每个原生Runner的新Context，均须取得同一输入代次内的两份新鲜捕获，才能执行实际任务。首次登录可沿用原有明确登录／登录奖励准备，密码、协议、下载、未知页和资源输入仍受原生门禁；账号绑定后再次进入登录页就停止，不代替用户重新登录。

流程内的日常→差分、日常→到期周常、CW循环中的逐局／积分／领奖都共享这个约束。首次绑定后不更换账号；两帧确认了不同账号即锁定失败，原绑定和原证据保留，后续游戏输入停止。单帧疑似错误会先阻止输入，只能由原账号的两份新鲜观察恢复，不能把一次错读当作已经切号或默认继续。

暂停或失焦导致输入代次改变时，旧证明失效，重新采集两帧；初始证明尚未完成时的长暂停也会丢弃暂停前帧，恢复后重新开始有限观察。观察窗为15秒且最多60帧，单次截图／OCR仍受原有超时约束，实际墙钟时间不能仅按帧间延时推算。正常同代次中UID暂时被页面遮挡时，保留本次已核实的上下文连续性，仍由原生页面、窗口和动作协议授权输入；不声称每个隐藏UID的画面都提供新的身份观察。

捕获时间须新鲜、代次一致，原生Context另提供采集序号，避免Windows同一时钟刻度的两次真实采集被当成旧帧。实际输入包括点击、键盘、拖动、移动、滚动、长按、交互、攻击、转视角和保存名等，均在原Context窗口外再检查身份；原生动作门禁没有移除。子视图沿用同一Runner的状态，不从旧视图或旧报告补造当前身份。

## 预算与结果

日常原账本先执行只读预检。未核对消耗、损坏或未完成的体力计划仍在游戏访问前阻止执行；账号核实后才允许`BattleBudget.begin`建立本次预算。账号不符时，原成功刷本账本也不会被重建成新账；正常独立日常保持原语义，未改变每次最多240已有开拓力的范围。

每个游戏步骤除原始报告与哈希之外，还必须有本次原生Context的账号证明，才会标记`account_verified=true`。单独返回一份历史成功报告、只读补存旧回执而没有当前观察，不能在父流程中被当作当前登录账号已完成；原生独立只读恢复入口仍保留。先前已经核实的日常、消耗和胜负保持，父流程失败不改写原子报告，也不新增局数、补资源或自动重试。

后续Context开始、证明提交及步骤完成时，会核对前序私人状态文件和裁剪证据的SHA-256。缺失、改写或超限会停止，不覆盖被改动的证据来掩盖失败。检查发生在跨步骤／重新证明边界，不能将其表述为持续监视文件或检测所有外部人工操作。

## 私人证据与界面协议

实现为[账号作用域](../autohsr/workflow_identity.py)、[Context接入](../autohsr/app.py)、[预算只读预检](../autohsr/recovery.py)及[流程执行器](../autohsr/task_workflow_run.py)。它不增加Settings字段，也不向配置、模型局面或新增界面状态中加入UID、账号指纹或安装路径。

本次流程目录中的`identity/state.json`记录本地账号指纹、原生运行目录、代次、捕获时间／序号及PNG来源与SHA-256。PNG仅裁剪底部UID区域，文件名使用随机值；它们是私人运行证据，不是公开素材或训练数据，继续随`runs/`忽略。不同账号的冲突观察单独保留，原绑定与原proofs不变。私人状态及来源读取有16 MiB上限；写入或替换失败不授权输入。

父报告新增`workflow.identity`，仅含以下状态，不含上述私人指纹或图像：

| 字段 | 含义 |
| --- | --- |
| `required` | 选中任务树是否包含游戏任务；本地记录工具不要求游戏账号 |
| `bound` | 本次是否曾完成账号绑定 |
| `verified` | 当前已登记的原生上下文是否均有有效代次证明，且未发生身份／证据故障 |
| `checked_contexts` | 有账号证明的原生运行目录数 |
| `observations` | 完整两帧证明数量，包括暂停后重核 |
| `account_changed` | 两帧确认不同账号；未读到UID不设为true |
| `status` | `not_required/not_observed/verified/needs_recheck/changed/evidence_invalid/storage_failed` |

状态保存后另发送`type='workflow_identity'`匿名事件，运行中的UI可据此更新，不应把`bound=true`替代当前`verified=true`。游戏子步骤增加`account_verified`；未核实时保留partial与原子报告。CW原报告已有的本地归属字段仍保持原含义，不用新状态包替代其当前账号／游戏周／局数及资源核验。

## 验证与限制

首轮新增19项账号检查，与原任务树、日常恢复、计划和CLI合计67项相关通过`runs/workflow-identity-related.log`（4.334秒）。后续增加长暂停及前序证据删改的3项检查，最终22项账号专项、30项任务树检查及旧周常／体力／历战等合计150项相关串行回归通过`runs/workflow-identity-final-related.log`（38.644秒）。

真实原生Context的窗口捕获循环和输入代理采用假窗口／OCR；日常协调器采用正式Runner及假Context。覆盖两个账号、两个步骤、暂停代次、未知／低置信度／冲突文字、旧帧、所有原生输入方法、私人状态及来源哈希、证据写入失败、旧账预检及身份不符不改写预算。所有UID与图片都是虚构测试输入，未以此宣称真实OCR识别率或实机账号切换已验证。

84项原GUI假后端检查通过`runs/workflow-identity-gui.log`。实际独立进程的本地记录CLI通过`runs/workflow-identity-cli-verification.json`，确认本地分析与导出不要求游戏账号，配置／记录原件保持、重复输出不覆盖，原匿名统计语义保持。14种原生输入方法覆盖、169个本地链接、现有上游来源不变及GPL核对通过`runs/workflow-identity-source-verification.json`。

早期`runs/workflow-identity-first.log`、`runs/workflow-identity-second.log`、`runs/workflow-identity-related-first.log`及`runs/workflow-identity-scope.log`失败记录保留。1741项全量快照曾与独立流程事件检查并行，4项旧周常被全局执行互斥拒绝；原`runs/workflow-identity-all.log`为失败记录，不能当作通过。独立复现与上述150项串行相关检查通过，未修改互斥来放行并发输入。最终源码哈希为`runs/workflow-identity-final-source-snapshot.json`；对应1745项全量串行检查通过`runs/workflow-identity-all-final.log`（802.308秒），检查前后6份Python源文件哈希一致。
