# 原生执行序列的账号连续性

更新：2026-11-01。此项覆盖[任务树后端](task-workflows.md)及独立日常／周常计划、货币战争循环／周常序列的跨步骤账号约束，尚未实机验收，不表示完整多账号配置切换、自动登录或全部玩法已经支持。新增账号检查只使用虚构UID、假窗口／OCR和本地临时文件；未访问当前真实账号、Player.log／缓存或安装目录，未新增游戏截图，也没有操作游戏、消耗资源或构建EXE。

## 本机配置方案

在「设置 → 游戏连接」点「新建副本」，可把当前已保存的设置复制为独立方案。若默认配置还未保存过，副本从程序默认值创建。命名方案写在默认配置所在目录的 `profiles.local` 下，每套方案使用自己的设置文件和定时计划目录。新建后继续使用原方案，选中目标再点「切换方案」即可应用。

切换前要结束运行和编辑，保存更改并停用当前方案中已启用的计划。切换时重新载入目标设置，保留窗口位置，并回到游戏连接页。通过常规入口重新打开助手时使用默认配置。

「设置方案账号」可为当前方案绑定 UID。输入内容遮盖显示，留空并确定可解除绑定。绑定变更与方案切换使用相同的空闲、保存和计划停用条件。副本需要单独绑定账号，定时计划也需单独创建。

绑定后，请先登录该账号并进入游戏主界面。执行器用两张当前画面核对 UID，账号不符时停止。日常先只读预查旧账，核验账号后才建立体力预算。暂停或失焦后，恢复操作前重新核验。定时任务沿用启用时冻结的绑定。

方案和本机定时回执保存 UID 的 SHA-256 指纹，用于和实际画面比较。公开运行报告只显示核验状态。登录由玩家单独完成，日常账本仍按实际核实的账号和游戏日记账。

## 独立计划与CW序列（2026-11-01）

[PlanRunner](../autohsr/plan_runner.py)、[CW循环](../autohsr/currency_wars_loop.py)及[CW周常](../autohsr/currency_wars_weekly_run.py)现在分别在整段执行期间持有共享的`sequence_lease()`和`sequence_identity()`。执行权覆盖日常→周常、逐局之间、积分→循环→领奖的间隙，并保持到总报告保存及最终`finished`回调结束；子Runner原有输入互斥和页面／预算门禁继续生效。另一线程或独立控制器不能趁子Runner已经退出而接管这段尚未结束的序列。

已有同线程外层任务树或原生序列时，子Plan／CW加入原租约和身份作用域，不更换账号绑定、私人证据目录或外层发布器，子序列退出不释放外层所有权。跨线程不能继承该权限，外层纯本地范围不能隐式升级为游戏执行范围；`workflow_lease()`仍拒绝嵌套任务树。持有租约本身不证明账号已核实。

正式原生Context继续通过两帧捕获和输入代理核验身份。可信注入factory仍负责其结果真实性，本轮没有向Plan／CW增加任务树的逐步骤`require_step`要求。独立序列因未到期、跳过或只读补存而没有运行任何游戏Context时，身份摘要保持`status='not_observed'`、`bound=false`、`verified=false`，可以保存本地结果，但不能将旧回执当作当前账号已核实。加入已有外层时摘要反映该外层的当前状态；没有新增Context就不新增子序列身份观察。

异常、停止和报告写入失败都会退出本序列自己的作用域。最终身份刷新只赋值给报告，不在保存前再次发送身份事件；初始化身份事件回调异常仍尝试保存原失败报告。`finished`回调异常发生在报告保存尝试之后，最终清理仍释放本序列租约，外层租约继续由外层负责。

## 当前行为

日常、差分与CW自己的账本指纹格式不同。流程使用[现有CW严格UID解析](../autohsr/currency_wars_identity.py)形成独立的本次绑定，不直接比较24位和64位旧字段，也不迁移或覆盖它们。UID仍须位于原生已知区域，完整8～10位ASCII数字、可信OCR及唯一候选共同成立，置信度至少0.85；重复、部分、低置信度或冲突不会取第一项。

每个原生Runner的新Context，均须取得同一输入代次内的两份新鲜捕获，才能执行实际任务。首次登录可沿用原有明确登录／登录奖励准备，密码、协议、下载、未知页和资源输入仍受原生门禁；账号绑定后再次进入登录页就停止，不代替用户重新登录。

流程内的日常→差分、日常→到期周常、CW循环中的逐局／积分／领奖都共享这个约束。首次绑定后不更换账号；两帧确认了不同账号即锁定失败，原绑定和原证据保留，后续游戏输入停止。单帧疑似错误会先阻止输入，只能由原账号的两份新鲜观察恢复，不能把一次错读当作已经切号或默认继续。

暂停或失焦导致输入代次改变时，旧证明失效，重新采集两帧；初始证明尚未完成时的长暂停也会丢弃暂停前帧，恢复后重新开始有限观察。观察窗为15秒且最多60帧，单次截图／OCR仍受原有超时约束，实际墙钟时间不能仅按帧间延时推算。正常同代次中UID暂时被页面遮挡时，保留本次已核实的上下文连续性，仍由原生页面、窗口和动作协议授权输入；不声称每个隐藏UID的画面都提供新的身份观察。

捕获时间须新鲜、代次一致，原生Context另提供采集序号，避免Windows同一时钟刻度的两次真实采集被当成旧帧。实际输入包括点击、键盘、拖动、移动、滚动、长按、交互、攻击、转视角和保存名等，均在原Context窗口外再检查身份；原生动作门禁没有移除。子视图沿用同一Runner的状态，不从旧视图或旧报告补造当前身份。

## 预算与结果

日常原账本先执行只读预检。未核对消耗、损坏或未完成的体力计划仍在游戏访问前阻止执行；账号核实后才允许`BattleBudget.begin`建立本次预算。账号不符时，原成功刷本账本也不会被重建成新账；正常独立日常保持原语义，未改变每次最多240已有开拓力的范围。

任务树的每个游戏步骤除原始报告与哈希之外，还必须有本次原生Context的账号证明，才会标记`account_verified=true`。单独返回一份历史成功报告、只读补存旧回执而没有当前观察，不能在任务树中被当作当前登录账号已完成；原生独立只读恢复入口仍保留。独立Plan／CW的可信factory契约与匿名身份摘要按上述范围区分。先前已经核实的日常、消耗和胜负保持，父流程失败不改写原子报告，也不新增局数、补资源或自动重试。

后续Context开始、证明提交及任务树步骤完成时，会核对前序私人状态文件和裁剪证据的SHA-256。缺失、改写或超限会停止，不覆盖被改动的证据来掩盖失败。检查发生在跨步骤／重新证明边界，不能将其表述为持续监视文件或检测所有外部人工操作。

## 私人证据与界面协议

实现为[共享执行租约](../autohsr/workflow_lease.py)、[账号作用域](../autohsr/workflow_identity.py)、[Context接入](../autohsr/app.py)、[预算只读预检](../autohsr/recovery.py)及各原生流程执行器。运行时观察不会写回配置。模型局面和界面核验状态均不含 UID 或账号指纹。

拥有身份作用域的外层运行目录中的`identity/state.json`记录本地账号指纹、原生运行目录、代次、捕获时间／序号及PNG来源与SHA-256。PNG仅裁剪底部UID区域，文件名使用随机值；它们是私人运行证据，不是公开素材或训练数据，继续随`runs/`忽略。不同账号的冲突观察单独保留，原绑定与原proofs不变。私人状态及来源读取有16 MiB上限；写入或替换失败不授权输入。

任务树父报告使用`workflow.identity`；Plan／CW报告使用同形状的`execution_identity`，仅含以下状态，不含上述私人指纹或图像：

| 字段 | 含义 |
| --- | --- |
| `required` | 作用域是否声明游戏账号约束；选中任务树的纯本地记录步骤不要求游戏账号 |
| `bound` | 本次是否曾完成账号绑定 |
| `verified` | 当前已登记的原生上下文是否均有有效代次证明，且未发生身份／证据故障 |
| `checked_contexts` | 有账号证明的原生运行目录数 |
| `observations` | 完整两帧证明数量，包括暂停后重核 |
| `account_changed` | 两帧确认不同账号；未读到UID不设为true |
| `status` | `not_required/not_observed/verified/needs_recheck/changed/profile_mismatch/evidence_invalid/storage_failed` |

任务树发送`type='workflow_identity'`匿名事件；独立Plan／CW在初始化和其自有作用域的观察发布时发送`type='execution_identity'`。加入外层时保留外层发布器，总报告结束前再刷新其匿名快照；界面不应把`bound=true`替代当前`verified=true`。任务树游戏子步骤另有`account_verified`；未核实时保留partial与原子报告。CW原报告已有的本地归属字段仍保持原含义，不用新状态包替代其当前账号／游戏周／局数及资源核验。
