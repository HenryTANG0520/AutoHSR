# 差分宇宙独立红点领奖

2026-11-05新增独立原生任务，用于领取已有奖励，不再为此请求新的演算。当前须将游戏打开在可核实账号的差分宇宙主页；不启动游戏、登录、处理月卡、退出旧局或自动导航到主页。原`--differential-universe --du-rewards`仍是演算附加领奖，原日常`--reward-only`仍只补每日实训，两者语义保留。

## 明确请求与结果

默认请求拟合等级、稳态数组、可能性画廊三类已有红点奖励。月下奇谭未授权时记为`skipped_optional_categories`，不会为了清红点使用卡带，也不会仅因此阻止任务流程继续。显式开启`use_cassettes`后才把月下奇谭加入本次请求；只使用首次可信余额冻结出的已有整百卡带，每次100，不随其他奖励或外部变化扩大额度。

以下为用法说明，本轮没有运行访问游戏的命令：

```powershell
# 已打开差分主页：只处理三类免费已有奖励
.\.venv\Scripts\python.exe -m autohsr --du-rewards-only
# 同一入口另明确允许已有月下卡带；本次参数不保存配置
.\.venv\Scripts\python.exe -m autohsr --du-rewards-only --du-use-cassettes
```

只能另配`--config`、`--game-path`及已有通知参数，不混入演算局数、接续、刷本、新预算、存档或通关后日常选项。不修改已保存`differential_universe_rewards`开关。

桌面入口为“旷宇纷争 → 差分宇宙 → 操作设置”，将“本次操作”选为“独立领奖”，再点右下“独立领取红点奖励”。默认领取上述三类免费奖励；“本次使用已有月下卡带（每次100）”须另行勾选。入口图同步显示所选范围和主页准备要求；切到设置、结果或运行记录时，原操作移至底栏，仍只有一个可见主按钮。

操作模式和卡带选项不计入保存设置，重开助手回到自动演算及卡带关闭；同一窗口中保留可见选择。点击开始时冻结本次选项，运行时锁定控件并复用暂停／停止。独立领奖忽略未保存的刷本、局数、编队及接续草稿；显式“保存设置”仍检查全部设置，并定位到相应可见字段。结果页展示所选奖励、可选跳过、剩余与卡带待核对项，不改写日常卡片、实训核实、演算局数或周积分结果。

`RunReport.du_rewards`独立保存`requested_categories`、`claims`、`remaining_categories`、`skipped_optional_categories`及卡带初始余额／额度／已核实消耗；不产生演算局数、通关、胜负或周积分领奖完成。`rewards_verified`只表示本次明确请求已核实；`all_notifications_cleared`另记全部可见红点是否清空，默认跳过月下时可以为false。请求内未完成或未绑定红点保持partial；已核实领取不会被后续失败抹掉。

## 输入与领取来源

[原生流程](../autohsr/du_rewards_only.py)复用既有[奖励页面与目标](../autohsr/du_rewards.py)，所有点击、返回和平移通过`Context.du_rewards_input`。通用点击／按键／移动不能在此操作中绕过；每个输入前重核当前画面、窗口、账号、run、代次、原PNG及已落盘意图。暂停、停止、失焦、证据或写盘失败按原生命周期释放输入，旧目标不重发。

- 拟合档位与当前等级／经验关联；奖励展示后核对同一视口、原档红点消失及其他红点未改。已领取档位数字从OCR消失，不视作换了奖励档位。
- 稳态数组绑定实际选中的页签、左侧分组、完整任务条件及本项已领取反馈；分组完成数增加不能充当已领取。
- 画廊绑定本次分类和完整阈值；领取后自动重排仍核对原阈值，不能因原行“领取”消失就清账。加权奇物无独立奖励进度入口时不补造入口。
- 月下奇谭保持解锁义务，经过技能／剧情与返回，余额恰减100后才核实本次消耗。每次下一笔之前重新核对剩余余额与冻结来源；未知或外部变化不继续使用卡带。

每次反馈需要两份不同捕获、不同PNG的对应画面；空帧、重复捕获、动画缺读打断连续来源。获得物品展示优先于背景主页文字，不能从独立旧展示或背景主页推断本次领取成功。

## 记录与再次运行

[独立记录](../autohsr/du_reward_store.py)写入本次`runs/<运行>/du-rewards.json`及规范入口`runs/du-rewards-session.json`，输入前双份内容必须一致，原PNG保留并核哈希。新的明确运行只在原动作、领取义务及返回来源均核实后准入；pending／submitted／unknown或未结清卡带义务不重放，也不能改走普通演算附加领奖绕过。

初始只读未能核实页面或用户停止，且尚无任何输入意图、领取或消耗义务时，保留失败来源并按明确“未提交输入”分支准入后续任务，不伪造账号或主页成功。已有任何未核实提交不适用此分支。原失败记录不删除，不以新运行覆盖原运行文件；没有自动断点接续或清账入口。

## 任务流程

可在[任务树](task-workflows.md)中明确选择：

```json
{"id":"du_rewards","type":"task","task":"du_rewards","params":{"use_cassettes":false}}
```

这是游戏输入任务，复用整段执行租约和账号连续性，必须先准备可核实的差分主页。单条可能路径最多一次独立领奖；循环乘算、互斥分支分开核对，选中子树不能隐藏重复定义。同一路径不同时启用旧演算`rewards:true`和新任务`use_cassettes:true`两个卡带消费入口；新免费任务可与旧附加领奖组合，旧演算任务的`rewards`默认仍为false。

父报告保留原子领奖数据与报告哈希，条件事实为`du_rewards_verified`，只代表本次请求。后续游戏任务仍受失败／未知阻断，不把红点结果写入`completed_runs`、`victories`或周常`score_rewards_verified`。桌面已接独立执行入口；任务树可通过CLI配置，桌面通用任务树编辑器与真实组合仍待交付，没有恢复整体UI设计任务。

## 来源与验证边界

继续使用已有公开脱敏主页／拟合／月下／稳态及画廊素材，没有新增截图或模型。固定March7thAssistant的周期积分领取和4.2邮件发放分支与本功能不同：右侧四类红点不能证明左下周期奖励已经领取。差分周常仍按原局数核验，周积分奖励保持单列未核实。

新增状态与异常分支使用假窗口、既有局部图及合成前后画面检查，真实稳态领取后、完整独立领奖和卡带路径仍须具体授权后验收。检查结果及原反例见[验证记录](../VALIDATION.md)，原差分独立通关计数保持不变。
