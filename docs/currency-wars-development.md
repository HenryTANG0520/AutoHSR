# 货币战争重启开发记录

## 2026-10-28：节点编号修复、标准继续与结算链

本轮在保留原生玩法和当前AutoHSR交互的前提下，参考[三月七货币战争](https://github.com/moesnow/March7thAssistant/blob/7cf6c6bed474539485d3b1504077ac352866829f/tasks/weekly/currency_wars.py)的局部字段识别、阶段观察和分段流程组织。没有复制其角色费用表、自动放弃旧局、失败重开或通用确认行为，也没有直接执行已安装的三月七程序。

### 已实现

- 战斗节点先定位图标框右边界及节点／百分比之间的短分隔线，再读取完整编号；原色与阈值化读数必须一致。支持语法中的两位数编号，不能通过截断`1-10`修复`1-1`。分隔线缺失、多个候选、读数冲突或置信度不足时保持未知。
- 原始全屏OCR保留，新增字段读取单独随隔离OCR结果及样本保存。旧样本仍能加载，历史单调时间戳仍不作为新鲜画面。短暂缺读只有限观察；明确读到另一节点则停止，均不重发出战。
- 标准节点的“继续挑战”绑定已经落盘并核实的出战及同编号胜利。反馈只接受同位面紧邻下一节点，或唯一高亮的下一位面；跳号、旧节点、冲突位面不算推进成功。保存逐节点历史。
- 支持已核实节点推进后自动展开的商店收起，核对到达来源、节点、金币和等级，再采集新备战阵容。该动作不购买或刷新。
- 下一位面导航绑定本次继续动作，后续环境确认核对对应位面的起始节点；未接通的投资／特殊节点仍停在明确的未支持边界。
- 第三位面对应最终节点的胜利，可以接续四步结算：最终胜利→评级→摘要→统计→大厅。每一步分别保存意图和反馈，缺前一页面证据、跳步、未知输入或账号变化不能标记整局完成。完成字段仍带`development_only=true`，开发接续不计入独立验收。

实现入口为[节点字段读取](../autohsr/currency_wars_node_ocr.py)、[标准推进](../autohsr/currency_wars_standard_progress.py)及[标准流程](../autohsr/currency_wars_standard_flow.py)。现有CLI、GUI入口和默认资源设置未改变；没有修改“UX/UI”对话负责的界面文件。
