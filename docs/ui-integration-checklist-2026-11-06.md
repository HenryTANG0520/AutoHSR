# AutoHSR 非货币功能界面接入清单

2026-11-06 · 界面接入准备。以 [P1 界面与交互指南](ui-ux-guide.md) 和 UI 分支 `ad02eb6` 为基准。核对主线 `9de3435` 与整合候选 `a195053`，后者包含周期四卡直接重抽和满额周期积分独立领奖。以下页面位置和文案供后端冻结后的接线评审。货币战争本轮暂停。

接线前的任务流与定时设计依据 `09e2beb` 和 `8deb079`。原方案拟用「任务编排」分类，以下工具整合核对记录现行路径。

## 工具部署与操作手册核对

当前工具接线路径统一为「设置 → 工具」，页内切换「跃迁记录、兑换码、通知、任务流、应用内定时、截图与识别」。下方旧「任务编排」位置属于接线前设计。发布时以同一提交的源码和验收记录确认版本，已安装正式包另按包内版本核对。

本次核对基线为中央整合 `3fb2372` 和任务流／定时面板 `21aa2d6`。前者已有跃迁、兑换和通知组件，后两页在独立组件提交。五页的统一构建与原生桌面布局待整体验收。

部署检查先记录整合提交，核对工具模块均在同一源码快照，再按发布流程用 `tools/build.ps1` 生成候选包。源码默认配置在项目根目录，正式包默认配置在 EXE 旁，两套数据分别核对。通知凭据在当前运行版的 `notifications.local`，由当前 Windows 用户保护。已有计划文件可以留存，重开应用后仍需明确启用。用隔离包和临时样本核对入口和回执后，再记录源码提交、包版本与桌面验收结果。

### 桌面操作与 CLI 边界

| 工具 | 桌面最短路径 | CLI 补充与写入边界 |
| --- | --- | --- |
| 跃迁记录 | 选本地记录、游戏缓存或链接文件，底栏显示对应读取动作。联网读取由用户选择明确来源，成功后可合并所选本地历史。选账号和卡池看统计及分页五星明细，再选账号范围和格式导出。SRGF 须明确选单账号。 | 单独读取本地记录时，导出前复核原件。联网记录及合并结果从已完成的内存快照导出。CLI `--warp-analysis` 默认只输出匿名统计，`--warp-details` 显式输出本地明细。指定联网卡池范围和页数上限仍用 CLI。[跃迁记录](warp-records.md) · [窗口统计与 Excel](warp-statistics-xlsx.md) |
| 兑换码 | 选择来源和国服或国际服后，可预览手动批次、本地码表或显式联网码表。底栏「开始兑换」独立执行本次批次。加入日常及成功后核对邮件为单独选项。 | 预览与逐码兑换回执分别显示。「由当前客户端识别」用于实际运行，预览须明确选择服务器。CLI `--redemption-check` 与 `--redemption-fetch` 分别核对本地与联网码表。持久化偏好用「保存设置」。[兑换码](redemption-codes.md) |
| 通知 | 可新建配置或导入 JSON，明确保存时以当前 Windows 用户加密写入凭据。选已保存方案后可「刷新」或「核对配置」。「加入通知名单」独立设置结束通知的目标。底栏「发送测试通知」本身就是一次明确发送请求，点击时重读并冻结方案版本。 | `--notify-profile-list`、`--notify-profile-check`、`--notify-profile-import` 提供同类本地管理，独立工具可指定 `--notify-store-dir`，`--notify-test` 对应显式试送。「运行结束通知」的「启用」、名单和结果范围控制以后符合条件的父运行自动发一次摘要。本次运行可用未保存草稿，普通设置仅显式保存。测试使用固定文案，与结束通知开关和模板分开。[通知](notifications.md) |
| 任务流 | 新建或打开任务流 JSON，精确的单步持续委托可用表单开关，任意流程仍可编辑 JSON。校验并另存后，运行默认整棵流程，也可选「指定步骤」并填写从 0 开始的路径。确认所选名称和预算后，显式运行已保存版本。 | CLI `--task-workflow-check`、`--task-workflow` 和定时目标可指定步骤路径。另存使用新文件，校验完整任务树。[任务流](task-workflows.md) |
| 应用内定时 | 新建或打开计划，保存并「预览预算」，核对同一修订的未来五次北京时间和单次触发整批上限。底栏「启用计划」复核同一已保存修订及预览依赖，冻结版本并启动本进程计时。「停用计划」影响选中计划的未来和待启动时隙，「停止定时」请求停止本控制器、取消待执行项并解除本进程启用。 | `--schedule-check` 检查定义，`--schedule-save` 和 `--schedule-list` 管理保存版本，`--schedule-preview` 同样给出未来五次日历时间，`--schedule-run` 显式开始计时。桌面激活预览读取设置和依赖版本，普通静态预算接口只计算预算。桌面定义位于当前配置旁的 `schedules.local`，CLI 独立工具可用 `--schedule-store-dir`。退出后重新启用。[应用内定时](schedules.md) |
| 截图与识别 | 打开单张本地 PNG／JPEG，或用底栏截取已有游戏客户区。截取后回到工具，在预览图上框选区域，读取原像素和归一化坐标，可对选区做 OCR 或另存 PNG。 | 截图需获得现有执行权，采集前后核对同一窗口来源和客户区几何。重新截取后须重新框选。读取本地图片和 OCR 共用工具执行线程。只有导出时写入用户选择的新文件，保留选区像素与透明度，去除原图元数据。图像及识别文字均在本地处理。 |

应用内定时与「周常计划」分别处理本进程计时和本次启动的到期资格。跳过启用所在分钟及错过的时隙，含游戏任务的外层重复仍限一次。「停止定时」与子 Runner 独立收到 F10 的运行停止路径分开核对。后者可停止时钟并清待执行项，进程内启用记录仍可能保留。

自动结束通知的候选桌面接线覆盖日常、普通计划、独立兑换、任务流和启用的定时目标。结束通知默认关闭，启用或保存动作只改变偏好，发送发生在匹配的运行结束时。已选方案若在点击试送前被同名替换，试送读取点击当时的版本。点击后的版本变化受提交门禁约束。定时页显示所选计划最近一次时隙，完整的子报告另查记录。

### 仅用测试替身的桌面验收清单

用虚构码、方案别名、假保存目录和临时设置。测试替身接管文件选择、组件、Runner、通知方案存储、通知传输、计时和回调。实际窗口操作、游戏输入、网络、Toast 与进程外发送设为失败哨兵。除显式保存用例外，记录配置和本地样本哈希应保持一致。计数分别观察 UI 请求、后端构造、假提交以及报告投影。

| 用例 | 操作与验收点 |
| --- | --- |
| R1 独立范围 | 在「加入日常计划」关闭时，选择本地码表并取消一次，确认零 Runner 调用。改手动输入 `aBc, ABC`，选择国服，关闭邮件，点一次「开始兑换」。假 Runner 收到一次独立 `redemption` 请求，原大小写保留，强制本次启用兑换。断言委托、刷本、每日奖励、普通邮件、勋礼、周常和新资源预算都未加入。取消、空手动输入、运行忙碌时零新增请求。 |
| R2 逐码回执投影 | 注入四条新回执，各为成功、服务端过期、已使用、无效，再加一条历史成功复用。另加码表过期、批次重复及未决意图。结果为新成功 1、三类服务端拒绝各 1、旧回执 1、预筛过期／重复各 1，状态为待核对。把原码、UID、意图标识、路径和原始错误填成哨兵字符串，结果卡上应无这些私有字段。 |
| R3 历史、未决与附件 | 注入原日常复用报告，显示「原批次成功」及旧回执，原批次数字与本次新成功分开。注入空批、不一致计数、报告未保存，各自保持明确状态。用后端回放的同账号／服／码记录重试未知意图，假提交增量为 0。另测逐码全核实、邮件未核实，验收要求逐码结果和附件待核对分开。 |
| N1 零发送 | 新建面板、切页、缩放重建、刷新、选择、核对、导入／替换、加入名单、改模板、勾选结束通知和保存设置，假传输全部 0 次。凭据导入可产生一次本地写入，输入文件仍保留。只导入或只选择方案不会加入名单或开启自动结束通知。 |
| N2 一次同意 | 使用可读方案 A 点一次「发送测试通知」，之后改选 B 并重建面板，最后执行捕获的假后台任务。假提交一次且为 A 的冻结版本、固定文案及独立测试键。再次显式点可得到新键。未选择、不可读、忙碌、渠道冲突和提交前停止时假提交增量均为 0。 |
| N3 回执与不重发 | 假传输分别返回受理、拒绝、未知，检查结果不含端点、凭据或远端原文。受理仅证明渠道接收本次测试，未知保持待核对，页面刷新和回调重复不增加提交。停止前已开始的假提交允许返回未知，保留本次回执。 |
| N4 结束通知单列 | 用假父 Runner 与假传输分别跑总开关关闭、空名单、不匹配结果范围和启用且匹配四种。前三种零提交，最后仅在父任务结束并释放游戏输入后产出一次摘要。保留原报告与原任务状态，通知未知不改写兑换成功，也不自动重复发送。 |

优先复用服务面板的假控件、`report_fixture()` 和记录式假任务队列，以及已有兑换与通知的后端回放。确认源码测试覆盖和桌面整条用例分别记录。

### 合入后的边界

- 只加入兑换时，首页预览和「开始计划」都包含这项任务。仅补领奖使用独立任务范围。[桌面开始条件](../autohsr/gui.py) · [计划任务列表](../autohsr/plan_runner.py)
- 逐码反馈与附件核验分别显示。通知页分开呈现运行结束和显式试送的回执。[兑换后端](../autohsr/redemption_run.py) · [通知报告](notifications.md#一次提交意图与回执)
- 最后一个计划在运行中停用时，旧任务继续受超时停止约束。假时钟和假 Runner 的复验覆盖这一边界。[桌面轮询](../autohsr/desktop_schedule.py) · [控制器](../autohsr/schedule_runtime.py)

## 后端冻结后逐项核对

- [ ] 每个入口确认正式操作名、可见页面前提、参数互斥、默认值及本次覆盖或显式保存规则。确认高难主页、备战、出战和领奖各自的可用范围。
- [ ] 每个结果确认字段、来源与归属。用运行状态显示「等待」「运行中」「已停止」；用各项回执显示「已核实」「已达成」「已领取」。明确失败保留原因，已发而反馈缺失保留「待核对」。核对旧报告缺字段、明确否定、零值及原结果复用。
- [ ] 每个新操作先验收正常、禁用、暂停／停止、错页、待核对和已达成。重点覆盖零局满额、达到开局上限、领到奖但回页缺证、培养草稿已发但尚未执行、委托暂无奖励。
- [ ] 按 P1 指南复查默认／最小窗口、五个一级页签、单一底栏主操作、焦点、显式保存及记录入口。先用假后端核对投影，再单列原生界面与实机验收范围。

## 任务流与定时的桌面验收情景

| 情景 | 核对结果 |
| --- | --- |
| 打开有效 JSON、修改草稿并校验 | 原文件内容保持一致，界面标明有编辑。校验结果显示通过或定位错误步骤。即使选中子树校验通过，整树无效时仍拦截另存。校验通过后继续编辑，应提示重新校验。 |
| 另存到空闲新路径，随后尝试重名或模拟并发创建 | 首次成功显示目标路径，回读结果与原有 JSON 解析器一致。`target_exists` 显示「目标已存在」，原件、已有目标及当前编辑均可核对。选择原路径时提示另选新文件。取消文件选择后回到另存入口。 |
| 原件在打开后被替换或删除，或另存后回读失败 | `source_is_current()` 返回否或收到 `source_changed` 时提示来源变化并保留当前编辑，提供重新加载和另选路径。`readback_changed` 显示「另存结果待核对」，可查看目标文件。另存到新目录时检查相对导入按新目录解析。 |
| 预览本地重复、游戏任务与互斥分支 | 本地目标最多十步、重复三次应显示三十步、零开拓力、零差分局。游戏目标外层重复超过一次或要求自动接续时提示原因。只领奖的开拓力上限为零；启用差分周常的组合目标显示条件上限。修改计划、目标或用于预览的设置后，旧预算应提示重新预览。 |
| 依次预览、保存、启用定时 | 用假时钟和假执行器观察。预览只显示整批上限。保存后计划可列出，状态为「未启用」。明确启用后显示下一次计划点及计时状态，按北京时间检查到期。启用所在分钟和错过的时隙跳过。修改已启用计划后核对修订变化提示，需重新启用。应用重启后状态回到「未启用」。 |
