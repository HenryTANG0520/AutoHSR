# AutoHSR 非货币功能界面接入清单

2026-11-06 · 界面接入准备。以 [P1 界面与交互指南](ui-ux-guide.md) 和 UI 分支 `ad02eb6` 为基准。核对主线 `9de3435` 与整合候选 `a195053`，后者包含周期四卡直接重抽和满额周期积分独立领奖。以下页面位置和文案供后端冻结后的接线评审。货币战争本轮暂停。

任务流与定时依据已通过整合检查的 `09e2beb` 和 `8deb079`，共用「设置」书页内的拟议「任务编排」分类。在分类内从入口列表分别打开「任务流」和「应用内定时」，返回恢复原入口焦点。

## 放置位置与完成条件

| 功能 | 拟放位置与操作 | 结果与边界 |
| --- | --- | --- |
| 混沌回忆、虚构叙事、末日幻影 | 「生存索引」内增设二级「逐光捡金」视图，三种玩法各一项。选定玩法后，底栏用「前往主页」。关卡与双队设置放在该玩法详情。 | 当前 4.6.0 三种主页均有正式 CLI 回执，可显示「主页已核实」。逐项显示「备战页已核实」「双队已核实」「已出战」「已结算」「已领取」。八槽、实际出战、节点交接和结算各读自己的证据。历史星数或成绩标「历史记录」。常规与星启各按当前布局提供选项。见[高难说明](challenges.md)。 |
| 差分周期演算结算 | 「旷宇纷争 → 差分宇宙 → 结果」沿用现有结果区。「详细记录」链接原报告和结算证据。 | 分列「本局获得积分」「本周积分」「拟合值」「解锁材料」和「周期积分奖励」。`periodic_settlement` 的缺读项显示「待核对」。面板观察可显示「可领取」，实际到账按领取回执。见[差分说明](differential-universe.md)。 |
| 差分独立积分目标与周常 | 独立演算放在差分「操作设置 → 演算计划」。随日常执行的目标放在「设置 → 周常计划 → 差分宇宙」，首页周常摘要只显示所选目标。「固定局数」显示演算局数，「达到积分上限」显示开局上限。 | 当前 CLI 的目标选择仅本次生效，默认固定局数。按原账号和游戏周显示「积分已满」或「已达开局上限，积分未满」。零局满额可达标。跨周或证据失效显示「待核对」，保留原已核实胜利；复用时区分「原周常结果」和「本次新增」。周期领奖另列。见[周常计划](weekly-plan.md)。 |
| 周期三／四卡重抽 | 差分「操作设置 → 演算计划」放「允许站点重抽」。周常采用同一能力时，在差分周常选项中明确本次范围。运行细节放差分结果与记录。 | 周期新局按原门禁处理。已校准的三卡路径须在游戏内二次确认，四卡路径直接换牌。显示「剩余重抽次数」「重抽已核实」或「已提交，待核对」。换牌和扣一次需同时有回执；读数缺失时留空。待核对后以原报告为准。见[差分说明](differential-universe.md)。 |
| 满额周期积分独立领奖 | 复用差分「操作设置 → 本次操作 → 独立领奖」。将「已有红点奖励」和「满额周期积分奖励」分成互斥范围，底栏按钮随所选范围命名。卡带选项归已有红点奖励。 | 周期范围从已打开的差分主页开始。分别显示「积分已满」「可领取」「已领取」「已返回主页」。物品和档位已核实、返回未核实时，保留「已领取」，同列注明「返回待核对」。只在本次领取链完整时标整体完成。见[独立领奖说明](du-rewards-only.md)。 |
| 培养材料预览与体力草稿 | 「生存索引」内的「培养目标」视图承载材料来源和费用，「预览材料」为本视图主操作。用户选定材料、地点和次数后，用「生成体力草稿」；审阅后通过「设置 → 体力计划」的现有列表应用。 | 分列「当前持有」「培养尚需」「候选来源」「预计开拓力」「本次实得」。配置上限标「按配置估算」，本次可用体力和建议次数按核实结果显示。「等级与行迹已完成」限于该培养目标。「草稿已生成」须有本次发布回执和匹配的草稿哈希；实付、实际执行次数和材料补足另核。见[体力计划](power-plan.md)。 |
| 持续委托 | 保留「每日实训 → 持续委托」卡及「设置 → 每日任务」原入口。领取反馈显示在卡片或运行详情。 | 反馈核实后显示「奖励已领取」和已确认的持续委托数量。无可领时显示「暂无可领取奖励」。点击后奖励或回页证据缺失显示「已提交，待核对」。4.6 的领取后状态为原委托继续累计，领取动作沿用原任务。见[每日流程](../DAILY_FLOW.md)。 |
| 任务流草稿 | 「任务编排 → 任务流」打开现有 JSON。用 `WorkflowDraft.load(path)` 读取，编辑 `draft.document`，用 `validate()` 校验并显示预算预留。首批主操作为「另存为」，调用 `save_as(path)` 写入用户选定的新文件。 | 分别显示「校验通过」「已另存」「目标已存在」「来源已变化」。校验只更新结果区。另存重新校验整树，并在磁盘回读核实后显示目标路径。目标重名、被并发创建或回读异常时保留当前编辑。来源变化时可重新加载或另选新文件。相对路径保留原文字，另存目录变化时用 `validate(destination=path)` 预览新解析位置。见[任务流说明](task-workflows.md)。 |
| 应用内定时 | 「任务编排 → 应用内定时」以表单列出目标、时间和重复设置。选定已保存计划或草稿后，用 `NativeScheduleExecutor(settings).preview_budget(plan)` 显示「单次触发整批上限」。计划保存和实际启用分别提供明确操作。 | 整批上限展示执行步数、日常开拓力和差分局数，包含重复次数，互斥分支对各项分别取最大值。字段缺失或校验失败显示原因；已核实零值照常显示。区分「预算预览」「已保存」「已启用」「等待触发」「执行中」和触发结果。启用基于已保存修订并冻结设置与依赖，应用运行期间才检查到期时间。见[应用内定时说明](schedules.md)。 |

| 文件 | 接线关注点 |
| --- | --- |
| [desktop.py](../autohsr/desktop.py) · [gui.py](../autohsr/gui.py) | 高难、培养视图复用生存索引和底栏。差分、周常与委托继续使用原运行锁、结果分发和记录入口。切页后核对主按钮仍对应当前操作。 |

## 后端冻结后逐项核对

- [ ] 每个入口确认正式操作名、可见页面前提、参数互斥、默认值及本次覆盖或显式保存规则。确认高难主页、备战、出战和领奖各自的可用范围。
- [ ] 每个结果确认字段、来源与归属。用运行状态显示「等待」「运行中」「已停止」；用各项回执显示「已核实」「已达成」「已领取」。明确失败保留原因，已发而反馈缺失保留「待核对」。核对旧报告缺字段、明确否定、零值及原结果复用。
- [ ] 每个新操作先验收正常、禁用、暂停／停止、错页、待核对和已达成。重点覆盖零局满额、达到开局上限、领到奖但回页缺证、培养草稿已发但尚未执行、委托暂无奖励。
- [ ] 按 P1 指南复查默认／最小窗口、五个一级页签、单一底栏主操作、焦点、显式保存及记录入口。先用假后端核对投影，再单列原生界面与实机验收范围。

## 任务流与定时的桌面验收情景

| 情景 | 核对结果 |
| --- | --- |
| 打开有效 JSON、修改草稿并校验 | 原文件内容保持一致，界面标明有编辑。校验结果显示通过或定位错误步骤。即使选中子树校验通过，整树无效时仍拦截另存。校验通过后继续编辑，应提示重新校验。 |
| 另存到空闲新路径，随后尝试重名或模拟并发创建 | 首次成功显示目标路径，回读结果与原有 JSON 解析器一致。`target_exists` 显示「目标已存在」，原件、已有目标及当前编辑均可核对。选择原路径时提示另选新文件。取消文件选择后回到另存入口。 |
| 原件在打开后被替换或删除，或另存后回读失败 | `source_is_current()` 返回否或收到 `source_changed` 时提示来源变化并保留当前编辑，提供重新加载和另选路径。`readback_changed` 显示「另存结果待核对」，可查看目标文件。另存到新目录时检查相对导入按新目录解析。 |
| 预览本地重复、游戏任务与互斥分支 | 本地目标最多十步、重复三次应显示三十步、零开拓力、零差分局。游戏目标外层重复超过一次或要求自动接续时提示原因。只领奖的开拓力上限为零；启用差分周常的组合目标显示条件上限。修改计划、目标或用于预览的设置后，旧预算应提示重新预览。 |
| 依次预览、保存、启用定时 | 用假时钟和假执行器观察。预览只显示整批上限。保存后计划可列出，状态为「未启用」。明确启用后显示下一次计划点及计时状态，按北京时间检查到期。启用所在分钟和错过的时隙跳过。修改已启用计划后核对修订变化提示，需重新启用。应用重启后状态回到「未启用」。 |
