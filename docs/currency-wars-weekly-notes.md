# 货币战争积分与周奖励核对

核对日期：2026-10-29。本文是后续适配的证据与差距记录，尚未实现货币战争周常入口或自动领奖；不表示已有完整周常功能。

## 上游行为

固定March7thAssistant提交`7cf6c6bed474539485d3b1504077ac352866829f`的[货币战争实现](https://github.com/moesnow/March7thAssistant/blob/7cf6c6bed474539485d3b1504077ac352866829f/tasks/weekly/currency_wars.py#L237-L303)将整局、领取奖励、核对积分与可选饰品提取串联。整局结果和奖励结果是不同返回值；不能把其中一项当作另一项成功。

- `check_currency_wars_score`在主页读取当前值／上限，要求上限18000，满分时保存时间戳。该状态供后续周期判断使用，不证明奖励已领取。
- `get_reward`检查积分入口附近的红点，进入面板，寻找“一键领取”，等待奖励展示后关闭并返回；本项目仍须分别核实当前入口、真实可领取状态和动作反馈。
- [周期奖励辅助](https://github.com/moesnow/March7thAssistant/blob/7cf6c6bed474539485d3b1504077ac352866829f/tasks/weekly/weekly_reward.py)另外处理助燃券满额提示，最多清理一次、重新领取一次。正常领取与满额提示是不同分支；清理后可能自动到账，也可能回到领取页，不能统一重发。

上述两个Python文件的Git blob分别为`52507ccfa8bf7977f8a8be9eca24050a6c16990d`与`f1dc22ae0f755c81ccc948520bb7fd02520ea751`。本轮仅只读核对，没有将辅助源码或按钮图导入运行资源；原生Runner结果修复仍使用AutoHSR既有代码。

## 与当前实现的差距

当前[入口导航](../autohsr/currency_wars_navigation.py)能识别积分奖励面板并返回主页；它没有自动领取动作。[连续运行](currency-wars-loop.md)按指定局数或直到停止执行标准开发局，没有积分目标。[周常计划](weekly-plan.md)的货币战争分支仍报告待接入，不能因为标准循环已可归档就改成周奖励完成。

后续需要交付：

1. 从当前新鲜主页／面板读取积分字段；识别一框与拆框文字，分开门槛、当前值、上限和其他资源。缺失、冲突、低置信度和其他上限保留未核实，不填0。
2. 按当前账号和北京时间周一04:00游戏周保存积分证据；积分达标与奖励领取分开。跨周、换号或未核实的旧动作不能重置为可重开状态。
3. 明确积分目标、最大局数与暂停停止。已经达标可跳过新的对局，未达标或读取失败不能谎报周常完成；每局继续使用原生账号、资源和归档协议。
4. 正常领奖须有当前可领取控件、独立奖励展示及返回面板的反馈；满额清理及清理后自动到账／仍可领取要分别处理。禁用、已领取、缺少按钮与动画不能混为同一状态。
5. 接入周常Runner和当前AutoHSR界面，保留原日常结果与每局报告。报告写盘失败或旧领取动作未知时不自动重放。

本轮未启动、检测或操作真实游戏，未消耗资源或重开旧开发局。全部三月七功能的目标保持，当前状态持续记录在[开发范围](development-roadmap.md)。
