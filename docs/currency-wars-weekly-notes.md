核对日期：2026-10-29。已新增独立积分核对；积分目标自动停止、货币战争周常及积分领奖尚未接入。本文同时保留来源证据与后续差距。

## 独立积分核对

源码CLI为`--currency-wars-points`，后端为`Runner(settings, emit, operation='currency_wars_points')`。使用现有准备和导航流程，到主页即停止导航；从已识别的难度、模式或积分面板只返回主页，不点击开始对局或积分领奖。准备阶段仍可能按原协议处理已拥有的免费登录补给。本轮仅核对CLI帮助，没有执行真实游戏操作。

```powershell
.\.venv\Scripts\python.exe -m autohsr --currency-wars-points
```

[字段解析](../autohsr/currency_wars_points.py)支持主页与积分面板，分开当前值／上限和奖励门槛，支持完整一框、两框及三框、合法千分位和全角文字。未知、重复、低置信度、截断、跨行、距离过大、数字片段关系不明或上限并非18000时停止核对，不填0或猜测数字。正式入口回到主页后，在同一新鲜画面核实UID和积分，最多三次有限重读。

报告`operation='currency_wars_points'`，`currency_wars.mode='weekly_points'`：

| 字段 | 含义 |
| --- | --- |
| `current`、`limit`、`points_verified` | 已读到的当前值与上限；0也是有效观察 |
| `score_complete` | 当前显示积分已满 |
| `game_week`、`observed_at` | 观察时的北京时间周一04:00游戏周与时间 |
| `period.verified` | 界面本期倒计时与该游戏周是否一致 |
| `weekly_target_verified` | 当前满分且倒计时一致；还须成功报告和有效回执共同核对 |
| `rewards_verified=false` | 本入口没有核实积分奖励领取 |
| `completion_verified=false`、`match_started=false` | 不是新对局、通关或独立验收记录 |

倒计时按可见的最细分钟／小时／天精度核对，允许120秒时钟差。刚跨周仍显示旧满分、倒计时缺失、冲突或不可读时，不把当前显示满分记为本周目标已核实。独立核对的报告success只表示积分观察及保存流程完成，不表示积分已满或奖励已领；积分字段缺失、账号不完整或保存失败分别报告失败／部分完成。

[观察与回执](../autohsr/currency_wars_points_run.py)保存到`runs/currency-points/<本地账号指纹>/<游戏周>/<观察ID>.json`，同目录`latest.json`指向最近记录。每次观察另存，不覆盖旧观察与原报告；原截图、限定OCR字段、原报告和回执均核对哈希。正式Runner在报告及回执处理完成前继续持有运行锁，回执失败会保持partial并释放锁。账号指纹只在本地用于隔离；限定文字不含UID、头像或无关余额，不进入决策模型载荷。客户端版本从当前进程目录的`game_version`读取，只保留版本、来源类型和哈希，不记录安装路径。

`latest(root, account, week)`用于读取指定账号／周的历史证据，并验证原图、字段、倒计时和报告。它不替代运行时的新鲜观察，也不授权开局、领奖或清理。已有未核实结束的标准会话会在游戏准备、窗口检测和热键前阻止积分导航；已完整结算的原会话可保留不动。手动进行中的未知页面不使用通用确认退出。

20项[专项检查](../autohsr/tests/test_currency_wars_points.py)覆盖真实Runner报告与回执、导航边界、零分／满分、拆框和反例、跨周旧显示、同周多次观察、旧对局保留、未知会话阻止、缺客户端版本、截图后代次改变、保存失败与锁释放、篡改、CLI及配置不保存。三份[脱敏文字夹具](../autohsr/tests/fixtures/currency_wars_points.json)仅筛选旧OCR原文／框／置信度并记原图与清单哈希，不带图像和账号资料；完整隔离OCR重读也得到相同积分。这些是旧校准及离线机制检查，GUI与真实入口仍待验证，详见[开发记录](currency-wars-development.md)。

## 上游行为

固定March7thAssistant提交`7cf6c6bed474539485d3b1504077ac352866829f`的[货币战争实现](https://github.com/moesnow/March7thAssistant/blob/7cf6c6bed474539485d3b1504077ac352866829f/tasks/weekly/currency_wars.py#L237-L303)将整局、领取奖励、核对积分与可选饰品提取串联。整局结果和奖励结果是不同返回值；不能把其中一项当作另一项成功。

- `check_currency_wars_score`在主页读取当前值／上限，要求上限18000，满分时保存时间戳。该状态供后续周期判断使用，不证明奖励已领取。
- `get_reward`检查积分入口附近的红点，进入面板，寻找“一键领取”，等待奖励展示后关闭并返回；本项目仍须分别核实当前入口、真实可领取状态和动作反馈。
- [周期奖励辅助](https://github.com/moesnow/March7thAssistant/blob/7cf6c6bed474539485d3b1504077ac352866829f/tasks/weekly/weekly_reward.py)另外处理助燃券满额提示，最多清理一次、重新领取一次。正常领取与满额提示是不同分支；清理后可能自动到账，也可能回到领取页，不能统一重发。

上述两个Python文件的Git blob分别为`52507ccfa8bf7977f8a8be9eca24050a6c16990d`与`f1dc22ae0f755c81ccc948520bb7fd02520ea751`。本轮仅只读核对，没有将辅助源码或按钮图导入运行资源；原生Runner结果修复仍使用AutoHSR既有代码。

## 与当前实现的差距

当前[入口导航](../autohsr/currency_wars_navigation.py)能识别积分奖励面板并返回主页，独立积分核对已接入，但没有自动领取动作。[连续运行](currency-wars-loop.md)按指定局数或直到停止执行标准开发局，没有积分目标。[周常计划](weekly-plan.md)的货币战争分支仍报告待接入，不能因为标准循环已可归档就改成周奖励完成。

后续需要交付：

1. 已实现的积分读取和账号／游戏周证据须继续覆盖真实布局变体、GUI与独立留出；旧校准与合成检查不能外推成全部客户端已支持。
2. 将积分证据接入循环及周常目标。跨周、换号或未核实的旧动作不能重置为可重开状态，不能只查历史缓存便授权新的输入。
3. 明确积分目标、最大局数与暂停停止。已经达标可跳过新的对局，未达标或读取失败不能谎报周常完成；每局继续使用原生账号、资源和归档协议。
4. 正常领奖须有当前可领取控件、独立奖励展示及返回面板的反馈；满额清理及清理后自动到账／仍可领取要分别处理。禁用、已领取、缺少按钮与动画不能混为同一状态。
5. 接入周常Runner和当前AutoHSR界面，保留原日常结果与每局报告。报告写盘失败或旧领取动作未知时不自动重放。

本轮未启动、检测或操作真实游戏，未消耗资源或重开旧开发局。全部三月七功能的目标保持，当前状态持续记录在[开发范围](development-roadmap.md)。
