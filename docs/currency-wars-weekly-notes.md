## 独立积分核对

源码CLI为`--currency-wars-points`，后端为`Runner(settings, emit, operation='currency_wars_points')`。使用现有准备和导航流程，到主页即停止导航；从已识别的难度、模式或积分面板只返回主页，不点击开始对局或积分领奖。准备阶段仍可能按原协议处理已拥有的免费登录补给。本轮仅核对CLI帮助，没有执行真实游戏操作。

```powershell
.\.venv\Scripts\python.exe -m autohsr --currency-wars-points
```

[字段解析](../autohsr/currency_wars_points.py)支持主页与积分面板，分开当前值／上限和奖励门槛，支持完整一框、两框及三框、合法千分位和全角文字。未知、重复、低置信度、截断、跨行、距离过大、数字片段关系不明或上限并非18000时停止核对，不填0或猜测数字。正式入口回到主页后，在同一新鲜画面核实UID和积分，最多三次有限重读。

报告`operation='currency_wars_points'`，`currency_wars.mode='weekly_points'`：

| 字段 | 含义 |
| --- | --- |
| `current`、`limit`、`points_verified` | 已读到的当前值与上限；0也是有效观察 |
| `score_complete` | 当前显示积分已满 |
| `game_week`、`observed_at` | 观察时的北京时间周一04:00游戏周与时间 |
| `period.verified` | 界面本期倒计时与该游戏周是否一致 |
| `weekly_target_verified` | 当前满分且倒计时一致；还须成功报告和有效回执共同核对 |
| `rewards_verified=false` | 本入口没有核实积分奖励领取 |
| `completion_verified=false`、`match_started=false` | 不是新对局、通关或独立验收记录 |

倒计时按可见的最细分钟／小时／天精度核对，允许120秒时钟差。刚跨周仍显示旧满分、倒计时缺失、冲突或不可读时，不把当前显示满分记为本周目标已核实。独立核对的报告success只表示积分观察及保存流程完成，不表示积分已满或奖励已领；积分字段缺失、账号不完整或保存失败分别报告失败／部分完成。

[观察与回执](../autohsr/currency_wars_points_run.py)保存到`runs/currency-points/<本地账号指纹>/<游戏周>/<观察ID>.json`，同目录`latest.json`指向最近记录。每次观察另存，不覆盖旧观察与原报告；原截图、限定OCR字段、原报告和回执均核对哈希。正式Runner在报告及回执处理完成前继续持有运行锁，回执失败会保持partial并释放锁。账号指纹只在本地用于隔离；限定文字不含UID、头像或无关余额，不进入决策模型载荷。客户端版本从当前进程目录的`game_version`读取，只保留版本、来源类型和哈希，不记录安装路径。

`latest(root, account, week)`用于读取指定账号／周的历史证据，并验证原图、字段、倒计时和报告。它不替代运行时的新鲜观察，也不授权开局、领奖或清理。已有未核实结束的标准会话会在游戏准备、窗口检测和热键前阻止积分导航；已完整结算的原会话可保留不动。手动进行中的未知页面不使用通用确认退出。

20项[专项检查](../autohsr/tests/test_currency_wars_points.py)覆盖真实Runner报告与回执、导航边界、零分／满分、拆框和反例、跨周旧显示、同周多次观察、旧对局保留、未知会话阻止、缺客户端版本、截图后代次改变、保存失败与锁释放、篡改、CLI及配置不保存。三份[脱敏文字夹具](../autohsr/tests/fixtures/currency_wars_points.json)仅筛选旧OCR原文／框／置信度并记原图与清单哈希，不带图像和账号资料；完整隔离OCR重读也得到相同积分。这些是旧校准及离线机制检查，GUI与真实入口仍待验证，详见[开发记录](currency-wars-development.md)。

## 独立普通领奖

后端为`Runner(settings, emit, operation='currency_wars_rewards', currency_rewards_resume=False)`，CLI如下；本轮没有执行真实游戏操作：

```powershell
# 核对并领取当前可领取奖励，不新开局、不清理满额助燃券
.\.venv\Scripts\python.exe -m autohsr --currency-wars-rewards
# 接续已核实步骤，或仅补存已经完成的原报告／回执
.\.venv\Scripts\python.exe -m autohsr --currency-wars-rewards --resume-currency-rewards
```

新运行先核对未结束标准对局与旧领奖记录，再复用准备／导航到主页，读取当前账号、积分、客户端和游戏周倒计时。每步正式输入前核对当前画面、UID、冻结客户端／识别设置、游戏周、落盘意图与代次；只能打开积分面板、点击当前可用一键领取、关闭本次奖励展示、返回主页。没有通用确认、购买、开局或清理输入。

控件必须在面板指定区域且唯一，OCR置信度与图像中的金色可用／中性禁用状态分别核实；低置信度重复仍构成冲突。缺按钮和暗色／遮挡保持未知，不作为已领取；明确无可领取文字只在控件区域有效。当前可领取时只提交一次，分别取得两帧一致的“获得物品”、正数量及关闭提示，再关闭一次；返回面板后另核实两帧不可领取状态，最后核对两帧同积分、同账号与倒计时一致的主页。等待有界，反馈未知不重发。

报告`currency_wars.mode='weekly_rewards'`，主要字段如下：

| 字段 | 含义 |
| --- | --- |
| `current`、`game_week`、`account_key` | 本次冻结积分、游戏周与仅本地使用的账号指纹 |
| `claimed_now` | 本次有独立奖励展示来源；初始已经无可领取时为false |
| `rewards_verified` | 当前可领取状态已结清且返回主页核实；还要求成功保存原报告与回执 |
| `weekly_rewards_verified` | 上述核实且积分已满18000；未满时不能宣称本周目标完成 |
| `completion_verified=false`、`match_started=false` | 不是对局通关或独立验收 |
| `phase` | lobby／panel／overlay／panel_after_claim／panel_settled／returned／blocked |

助燃券满额须有独立两帧提示，记为`blocked`与partial，原领取动作的结果为`fuel_ticket_limit`，不记奖励已到账、不点清理、不重试领取。满额清理及清理后的自动到账／仍可领取分支仍待适配，不能用本入口越过。

数据位于`runs/currency-weekly-rewards/<尝试ID>/session.json`，入口为`currency-weekly-rewards-current.json`，完成回执为同目录`receipt.json`。意图在输入前落盘，原图、限定OCR字段、可用状态与两帧时序留存；写回执时再从原图和字段重建页面、积分、数量与控件状态，不只信完成布尔值。字段不含UID及无关账号文字，原图与目录保持本地。每次尝试另建目录，完成后保留原件。

未完成、未提交回执或证据改变的领奖记录会在其他Runner准备游戏前阻止新输入，只读识别仍可用。明确接续仅从已核实阶段继续；pending／unknown输入在游戏访问前拒绝，不重放。跨周的未完成输入目标也拒绝接续。已经完整返回且原报告／回执保存失败时，可以依据原证据只读补存新审计报告：不检测、导航或操作游戏，不改原失败报告；回执记录原报告路径、存在时的哈希及`read_only_recovery`。此恢复不把旧失败文件改成成功。完成目录和原图／报告任何变化仍会阻止后续输入。

19项[专项检查](../autohsr/tests/test_currency_wars_weekly_rewards.py)使用正式Runner／Context、假窗口、合成OCR与按钮图像，覆盖领取／禁用、零分与满分、满额拆行、未知不重放、已核实步骤接续、报告及回执失败只读恢复、原图重验与伪造状态、账号／版本／代次／写账门禁、返回原子保存、其他Runner隔离与CLI不保存配置。114项积分、循环、领奖、导航及准备整合通过`runs/currency-weekly-rewards-release.log`（41.710秒）。正向领奖没有真实游戏样本，原438幅旧图扫描仍未找到已校准的一键领取正样本；这些机制检查不能写为真实领取或完整周常已验收。

## 上游行为

固定March7thAssistant提交`7cf6c6bed474539485d3b1504077ac352866829f`的[货币战争实现](https://github.com/moesnow/March7thAssistant/blob/7cf6c6bed474539485d3b1504077ac352866829f/tasks/weekly/currency_wars.py#L237-L303)将整局、领取奖励、核对积分与可选饰品提取串联。整局结果和奖励结果是不同返回值；不能把其中一项当作另一项成功。

- `check_currency_wars_score`在主页读取当前值／上限，要求上限18000，满分时保存时间戳。该状态供后续周期判断使用，不证明奖励已领取。
- `get_reward`检查积分入口附近的红点，进入面板，寻找“一键领取”，等待奖励展示后关闭并返回；本项目仍须分别核实当前入口、真实可领取状态和动作反馈。
- [周期奖励辅助](https://github.com/moesnow/March7thAssistant/blob/7cf6c6bed474539485d3b1504077ac352866829f/tasks/weekly/weekly_reward.py)另外处理助燃券满额提示，最多清理一次、重新领取一次。正常领取与满额提示是不同分支；清理后可能自动到账，也可能回到领取页，不能统一重发。

上述两个Python文件的Git blob分别为`52507ccfa8bf7977f8a8be9eca24050a6c16990d`与`f1dc22ae0f755c81ccc948520bb7fd02520ea751`。其思路现已改写为原生普通领奖与独立满额观察，没有迁入输入框架或按钮图；完整满额处理仍待适配，来源与GPL v3见[清单](../assets/upstream/March7thAssistant/source.json)。

另核对原始[功能请求#1260](https://github.com/moesnow/March7thAssistant/issues/1260)及[合入改动#1261](https://github.com/moesnow/March7thAssistant/pull/1261/files)：报告确为周期奖励因助燃券上限受阻，新增辅助在清理后等待奖励展示，仅回到领取页才再领一次。它没有给出清理前后完整库存／资源变化的核验契约；原报告的外部附件本次只读请求返回HTTP 403，未取得可核对像素。因此仍需补齐清理按钮、后续页面和资源结果的来源，不能从一个文本“清理”推断所有清理场景等价。本次没有点击实际清理或绕过附件访问限制。

## 与当前实现的差距

2026-10-30另接[整局失败结算与循环停止规则](currency-wars-defeat-loop.md)。已核实失败消耗原上限，汇总与胜利分列；默认留档后停止，明确接续仅使用原目标剩余局数，周常保留原日常。积分、领奖和整局胜利仍为不同事实，失败页面几何及真实组合尚未验收。

当前[入口导航](../autohsr/currency_wars_navigation.py)能识别积分奖励面板并返回主页，独立积分核对与普通领奖已经分别接入。[连续运行](currency-wars-loop.md)支持可选的本周积分目标，达标可零局停止，未满仍受局数上限约束；冻结游戏周、绑定账号并核对精确原回执，已有对局先完成、空记录留档，跨周不自动迁移。独立循环不自动领奖；[周常计划](weekly-plan.md)现已顺序调用积分、有限循环及领奖，只有完整原报告与周回执成立才接受周完成，不能仅凭标准循环或积分达标改成奖励已领。

后续需要交付：

1. 已实现的积分读取和账号／游戏周证据须继续覆盖真实布局变体、GUI与独立留出；旧校准与合成检查不能外推成全部客户端已支持。
2. 循环已使用积分证据、局数上限、暂停停止及原目标接续，周常后端亦已接通；继续验证真实完整路径。跨周、换号或未核实旧动作不重置为可重开状态，不以历史缓存授权新输入。
3. 已达标可跳过新局，局数耗尽但未满记为exhausted／partial，读取失败保留active；这些结果继续与周奖励完成分开。每局沿用原生账号、资源和归档协议。
4. 普通领奖已有当前可领取控件、独立奖励展示、面板状态和返回协议，仍待真实布局及完整路径验证；满额清理及清理后自动到账／仍可领取要分别接入。禁用、已领取、缺少按钮与动画继续分开处理。
5. 周常Runner已保留原日常结果、每局与领奖报告，仍须整合当前AutoHSR界面。报告写盘失败或旧领取未知时不重放，回执恢复只读核实原始来源。

本轮未启动、检测或操作真实游戏，未消耗资源或重开旧开发局。全部三月七功能的目标保持，当前状态持续记录在[开发范围](development-roadmap.md)。
