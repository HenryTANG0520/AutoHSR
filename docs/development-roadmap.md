# AutoHSR 重启开发范围与实现状态

更新日期：2026-10-29。本文记录当前用户目标及实施进度，不取代历史验收，也不把上游存在的功能写成AutoHSR已实现。

## 当前目标

保留AutoHSR已有功能，将[三月七启动器／March7thAssistant](https://github.com/moesnow/March7thAssistant)的功能逐项学习、适配到AutoHSR，沿用当前AutoHSR交互逻辑。用户已澄清此前“绝区零一条龙／AutoZZZ”是目标描述笔误；不向本项目混入绝区零执行能力。

“UX/UI”对话负责当前桌面设计，本开发工作不修改其界面文件。现有日常、差分、预设编队、资源记账、暂停停止、报告及配置保存语义继续保留。旧报告中建议直接采用上游GUI属于当时的候选方案；本次目标明确采用现有AutoHSR交互，优先对接后端能力。

对照基线为March7thAssistant提交`7cf6c6bed474539485d3b1504077ac352866829f`。入口核对依据是[任务注册表](https://github.com/moesnow/March7thAssistant/blob/7cf6c6bed474539485d3b1504077ac352866829f/utils/tasks.py)、[默认配置](https://github.com/moesnow/March7thAssistant/blob/7cf6c6bed474539485d3b1504077ac352866829f/assets/config/config.example.yaml)、[README](https://github.com/moesnow/March7thAssistant/blob/7cf6c6bed474539485d3b1504077ac352866829f/README.md)及[任务实现目录](https://github.com/moesnow/March7thAssistant/tree/7cf6c6bed474539485d3b1504077ac352866829f/tasks)。此基线外新增的上游能力需要另行核对，不能从注册表推导其实际成功率。

## 实施顺序和当前进展

标准部署／交换后的盛会之星现有独立协议：由本次移动来源进入，完整候选与可用确认分开核实，再重采全部角色并完成移动回执。两／三卡已用旧画面校准，一卡及四至六卡仅为合成检查；其他特殊弹窗与星徽仍待适配。详见[最新开发记录](currency-wars-development.md)。

1. 保留既有日常、差分和桌面，先修复货币战争已知失败并接通可核实的节点、结算流程。本轮代码与证据见[货币战争重启开发记录](currency-wars-development.md)。
2. 已接入标准购买、经验支付、受限刷新、备战整理及相应收据、三种购买与成长偏好、合法满员交换和双向身份核验，另有14类装备与已读配方的逐件穿戴／合成。当前奖励覆盖普通／高级武装箱已识别装备、邀请函现金和四／五组补给；补给选择、确认、装备到账和角色重采分别核实。聘用书／邀请函角色已补命名选择与实际角色新增／升星核验，领取数量、费用、星级分开，原装备保留；聘用书仅有合成布局。顾问选择支持完整阵容不变分支，记录选择被接受，角色到账与后续商店报价分别记证；其他未开箱子在重采期间保护，逐箱交付。部分投资策略已接入原生选择／确认、声明赠箱的逐箱交付及收费刷新赠经验；一／二／三卡采用逐卡关系核验，未知完整效果不默认选择。继续补全局重排、在场角色出售／自定义保留名、角色全身重铸及消耗品其余规则、未知补给装备／多件补给、星徽／投资策略角色／改造型策略与特殊节点。刷新支持当前按钮0～99费用，每节点最多六次／十二金币；出售核实当前+0～99返还、来源空位及其余十八格。多个赠经验规则叠加、其他额外金币或经验、溢出奖励占位、多件补给等效果仍未接通。上游固定费用表、自动放弃旧局及失败重开不直接移植。
3. 建立后端任务适配和配置快照协议，再接入计划、周常、挑战、工具、外部引擎及云后端。现有Runner保持唯一输入所有者，任务接口稳定后交由当前UI呈现。
4. 根据[差分优化评审](march7thassistant-du-review-2026-10-28.md)逐项实施有明确收益的变化，先用现有回放验证，不为比较而重新刷十局。
