## 固定观察字段

| 字段 | 可固定读取的画面 | 判定边界 |
| --- | --- | --- |
| `page`、`achievement_total` | 总览独立核对「成就」、横向分类卡和底部「达成成就」及其数值。 | 达成数用于对照回页，本次两例均保持原值。 |
| `bulk_control`、`category_badge` | 总览右下整块一键按钮区、同一张分类卡上的红叹号。 | 可见金色、清楚缺席和未知分别记录。遮挡、滚动导致原卡离屏、只有 OCR 漏字均保留未知。 |
| `receipt_total`、`confirm_visible`、`receipt_rows` | 专属标题、底部「总计获得」旁星琼图标和数量、「确认」，明细的分类、成就名、每行数量和勾。 | 明细可滚动，分类标题和部分行会离屏。汇总与可见行分开。未看到完整滚动范围时，只记录所见行。 |
| `reward_item`、`reward_quantity`、`dismiss_visible` | 通用「获得物品」的同一卡片上星琼名称和数量，及「点击空白处关闭」。 | 只在已有同次专属明细并连续转场时关联此次一键领取。即使遮罩下能看见成就标题和卡片，也仍是遮罩阶段。 |
| `stellar_jade_balance` | 领取前后在同一跃迁页核对右上星琼图标旁数值。 | 相邻票券数独立。没有可配对的余额时记为未知。 |
| `row_after` | 回到同一分类后，原成就名所在行的完成状态、日期及奖品勾。 | 两段公开录像均保留未知。 |

在 1280×720 的 P2 样本里，一键按钮区约为 `[934, 620, 1143, 675]`，专属明细标题为 `[570, 60, 710, 105]`，汇总为 `[558, 582, 723, 624]`，确认按钮为 `[515, 645, 765, 690]`。通用遮罩的奖品卡在 `[597, 308, 683, 424]`。跃迁星琼图标和余额约为 `[1086, 26, 1162, 59]`。分类红标要随原分类卡定位。坐标为原视频像素中的左、上、右、下，适用于复放定位。

只读分类器在 P2 两张领取前总览及两张回页总览识别一致，在通用遮罩阶段拒绝把底层页当作回页。2374.500 秒曾因分类标题离屏而无法确认。新分支在同一专属标题、总计和确认控件之外，要求至少两条各自具备左侧明细、浅色行带和同位右端圆勾的完整行。P2 的 2371.200、2372.500 和 2374.500 秒通过回放。夹具保留旧读数。独立 P6 复放覆盖仍能看见分类标题的布局，其他来源的离屏布局待验收。

## 离线单次协议

`AchievementBulkReplay` 使用调用方已核实的 4.6.0 窗口、当前本地账号指纹和输入代次。它接收画面和离线发送记录。每个输入阶段都要用两张连续帧和第三张发送前新帧核对唯一控件。意图记录绑定该控件、画面和 OCR 摘要，使用排他文件创建并刷新到磁盘。确认意图另外绑定原一键意图、原发送记录和首次核实的专属明细总额。发送记录核对同一范围、时效及原件后单独落盘。每个目录只容纳一次尝试。发现已有意图或发送文件时保留原件并拒绝重新开始。短发、未知或中断后保留已核实事实。

| 阶段 | 记录 |
| --- | --- |
| 一键按钮 | 既有总览判定、唯一金色按钮和一致的达成数及分类顺序。发送结果单独记在 `bulk_input`。 |
| 专属明细和确认 | 在原领取之后核对专属页、正整数总额和唯一底部确认。先冻结 `receipt_total`，再单独记录 `confirm_input`。首次读取仍要求分类标题。已进入同次面板后，滚动版可用相同的汇总数、专属标题、明细行和确认栏复核。 |
| 通用遮罩 | 只在本次确认后的时限内接受新双帧，核对星琼名称、数量和关闭文字，且数量与明细相同。结果记在 `overlay_quantity`。 |
| 回页 | 遮罩退出后双帧核对同组分类顺序和原达成数。回页与控件清除分开记录。清除需要调用方验证原红标与控件区域完整可见，同时原按钮区域通过画面及 OCR 核对。 |
| 余额归因 | 从同一跃迁页分别读取星琼图标旁的领前和领后余额。余额差额与归因分开记录。只有回页、控件清除、同额物品和明细、以及已核实没有其他星琼收支的区间全部成立，才记录 `jade_attributed`。 |

离线调用方提供账号与窗口核验、红标消失、星琼图标及收支区间的原始核验结果。协议验证它们的配对和时序。P2 有领前和领后余额，可离线复放到账 20。P6 的物品展示和回页核实到 50，余额留空。协议以外的人工关闭仅作为回页观测。[离线协议](../autohsr/achievement_bulk_protocol.py) · [协议回归](../autohsr/tests/test_achievement_bulk_protocol.py)

62 项相关回归通过。P2 的 16 张原帧用模拟发送记录串起完整协议，P6 的四张独立原帧核对了页面及 50 星琼的两处展示。实机输入和当前账号的到账未验收。

## 独立前台入口

成就领奖默认关闭。已在 4.6.0 成就总览并看见金色「一键领取奖励」时，可显式执行独立命令。游戏须已运行并保持前台。

```powershell
.\.venv\Scripts\python.exe -m autohsr --achievement-bulk-claim
```

入口只提交一次金色按钮和一次当前专属明细的「确认」。两次分别冻结相邻画面、截图摘要和意图。原生点击前再次核对进程窗口、客户区、当前 UID 与弱冲突 UID、安装配置原件及版本、输入代次、唯一目标、原证据及 F10。成功报告发布期间也保持安装原件的 Windows 读锁。获得物品双帧通过后，手动关闭物品提示，程序在当前账号上观察回页。报告将发送、明细总额、物品数量、回页和控件清除分开。

可从 16:9 的角色活动跃迁页开始采星琼基线。日志提示后手动打开成就总览，回页确认后手动打开同一跃迁页，程序有界读取双帧余额。此路径能记录领前、领后和可比差额。手动区间无法证明没有其他星琼收支，`jade_attributed` 保留未知。未采到余额时同样保留未知。

原生执行权下，`runs/achievement-bulk-pending.json` 在首次动作前排他发布。新运行先核对该记录。只有完整证据表明领取与确认均未提交，或专属明细、物品及回页全部通过且原控件清楚消失时，终态记录才允许下一次运行解开门禁。释放前复核原报告、意图、发送及截图摘要。持久化失败、短发送、断续、回页区域待核或旧证据变化均保留未决状态。

74 项相关回归通过。CLI 回归使用假 Win32，通过正式 Context 核对两次发送、停止与失焦、弱 UID 冲突、证据变化、跨运行旧意图、余额差额及终态释放。标记和余额图标的判读复放了两条 4.6 原录像。当前账号和窗口的端到端实机仍待验收。[前台桥接](../autohsr/achievement_bulk_claim.py) · [CLI 回归](../autohsr/tests/test_achievement_bulk_claim_cli.py)

## 复放与采样

[固定字段夹具](../autohsr/tests/fixtures/achievement_return/bulk_reward_4_6.json)记录源片、帧号、遮挡范围、SHA-256 与预期读数。P2 为 2026-10-02 的原录屏，P6 归于 2026-09-28 发布的合集，按 4.6 版本期归档。复放用 B 站 q64 的 1280×720 码流。17 张脱敏帧已核对摘要、遮罩、画面标志和数值。两个原作者的录屏图像用于本地核对，仓库保存字段转录。文件名和哈希以夹具为准。

当前账号的最小实机取样需要同窗口、同账号的一段连续客户区记录。保留两张有金色按钮和分类红标的总览、目标分类中可领行、完整专属明细与确认、通用物品数量、关闭后两张稳定总览、以及重新进入原分类后同一行的完成日期及奖品勾。如需核对实际到账，领取前后各补两张同一余额页，在这段间隔内保持星琼无其他来源或去向。
