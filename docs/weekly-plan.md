# 日常与周常计划

## 日常交接与差分回执

计划报告在 `weekly_plan` 分开记录子报告的 `daily_status`、`daily_report_saved` 和本次 `daily_handoff`。所选日常全部结束、原报告已保存，且所选实训奖励已核实、没有待核对开拓力或沉浸器时，交接才记为 `complete`。勋礼或邮件仍待核对时，已核实的实训、资源消耗和原子报告继续保留，交接记为 `needs_review`，周常未开始。明确接续原货币周常时，已有日常引用仍按原协议核对，交接记为 `reused`。

派发到期周常前，重新核对日常原报告的目录、返回内容及本次子运行的账号证明。父报告的 `daily_source` 保存已核实的原报告路径与摘要。阶段回调或暂停后原报告发生变化时，保留原日常的已核实事实，周常不派发。明确接续货币周常的旧日常引用仍按原接续协议核对。

到期差分在暂停恢复后、创建子流程前重新核对冻结的游戏周。同一执行序列的后续子流程须重新核实账号，完整的低置信度账号反证可阻止交接。同一子流程、同一输入代次内已经核实账号时，正常隐藏账号区域的页面仍可通过原页面门禁。

固定局数周回执和积分回执在实际替换前核对原意图、子报告和原图。Windows 共享锁重试期间释放读句柄，每次重试重新核验。停止、跨周或证据变化会保留原意图与已核实局数，等待核对。实机的日常接周常仍待验收。

新固定局数回执在原生差分子报告中保存账号、游戏周、运行目录与唯一意图的绑定。只计独立新开局。各局 ID 和证据文件路径须唯一，开局／胜利／返回三张原图组成的哈希组也须唯一。旧版固定局数成功记录缺少这种归属证明时，保留原件并阻断自动复用和新开局，等待人工核对。旧待核对记录同样保留。既有具备原生绑定的积分回执仍按原协议核验。

## 2026-11-01：整段序列的执行权与账号连续性

独立`PlanRunner`从日常开始到到期周常结束，共享一份序列输入租约及账号作用域，覆盖子Runner之间的间隙，并保持到总报告保存和最终`finished`回调结束。独立CW循环及CW周常的积分→循环→领奖也使用同一机制。位于同线程外层任务树或序列中时复用外层租约、账号绑定及发布器，子序列不提前释放外层执行权；跨线程不能继承权限，仍禁止嵌套另一棵任务树。

正式Context在各子运行中分别取得同代次两帧账号来源，再由输入代理在实际输入前复核身份。换号或证据故障会阻止后续输入，先前日常、逐码兑换、资源消耗与CW胜负结果保留。子流程原有预算、游戏周、局数、领奖来源和恢复协议继续独立核对；持有序列租约不新增预算，也不证明周常已完成。

父报告`execution_identity`及同名匿名事件仅提供绑定／当前核实状态、Context数等摘要，不含UID、指纹或私人证据路径。独立计划没有运行Context时，例如未选日常且周常未到期，或只读补存，保持`not_observed`，不把旧结果当作当前账号观察；复用外层时展示外层当前摘要，不补造本子流程证明。可信注入factory负责结果真实性，本轮未新增任务树的逐步骤`require_step`要求。详细字段、异常释放和私人证据范围见[账号连续性](workflow-account-continuity.md)。

新增[Plan序列检查](../autohsr/tests/test_plan_sequence_scope.py)使用真实Context身份代理、虚构账号帧、假窗口／OCR及内存租约后端，覆盖同账号交接、换号阻止第二子输入、旧代次、跳过和报告／回调异常。源码接线与这些离线机制检查均不代表真实日常→周常、跨玩法暂停恢复或CW完整组合已验收；本次没有启动游戏或恢复旧开发局。

## 入口与时间

旷宇纷争的货币战争入口显示当前周常安排，仍保留整局未验收及只读独立操作的状态。差分入口“本次局数”属于独立运行，不替代周常局数。没有记录时查看结果置灰；执行中为查看进度，结束有报告后为查看结果，异常但没有报告时为查看状态。周常执行中断的原因保留到设置更改或下次运行，普通时间刷新不会将其改回到期预览；已经生成的报告不被后续异常覆盖。

首页右下“开始计划”执行当前表单的日常，并在日常完整结束后处理到期周常。首页以两行显示日常项目、预计开拓力和周常安排。检测窗口、进入游戏位于“设置 → 游戏连接”；暂停和停止只在执行期间出现。

“周常计划”直接打开设置中的同名页，可启用周常、选择玩法、星期、北京时间及局数。默认关闭，默认星期一04:00，1局；差分显示“演算局数”与预设，货币战争显示“对局上限”并隐藏差分预设。HH:MM采用24小时制，局数范围1～10。只有“保存设置”持久化配置；执行、检测和仅补领奖使用快照。

预设编队也可在周常页填写，与独立演算共用同一预设。输入不合法时界面直接定位字段，修正后仍执行原来的计划。未启用周常时，时间草稿不会阻止日常启动；显式保存仍检查全部配置，不能写入无效时间。

游戏周从北京时间周一04:00开始。自定义时间落在当前游戏周内，到期后下次“开始计划”执行，错过当分钟不会丢失当周资格。周一00:00～03:59属于上一游戏周末段。执行快照冻结开始时的游戏周；中途跨越刷新点不追加第二周。这里没有创建Windows定时任务、系统唤醒或后台定时启动。

界面持续打开时，预览随时钟跨过计划时间和游戏周刷新点更新，不需要修改设置或重开窗口。运行与暂停期间保留本次进度；同一游戏周内保留已完成／已跳过结果，跨周后再显示下一次点击时的资格预览。上一周的结果仍保留在摘要及原报告中，摘要标明“上次计划”，周常详情以原游戏周日期代替相对的“本周”。较新的独立玩法结果不会被重新标记。待核对、停止、缺少游戏周或报告未保存等未解决状态持续保留；改变时间不会清账、认定账号完成或触发执行。

重开助手后，若首页提供原周常接续，日常卡片同步显示经过原报告哈希核对的“原日常”结果和实际挑战／消耗；原报告未包含的任务显示“本次不执行”，不显示新草稿的预计费用。没有原日常的周常目标全部显示“本次不执行”。查看卡片只打开对应结果或安排，不加入新日常；后续计划的草稿仍可在设置中编辑，修改草稿不改变当前接续范围。当前窗口刚完成的日常仍保留其真实执行结果。原报告改变或来源核对失败时，不展示为原日常完成，也不提供接续按钮。

## 差分周常周期积分目标

配置启用差分周常后，`--plan --du-until-points` 对本次到期周常使用积分目标。`weekly_runs` 的 1～10 局成为冻结的开局上限。独立演算继续用 `--du-runs` 指定局数。CLI 选择只作用于本次计划，平常的 `--plan` 仍执行固定局数。

```powershell
.\.venv\Scripts\python.exe -m autohsr --plan --du-until-points
```

首次开局前及每次胜利返回后，原生 `PeriodicPointsGoal` 从差分主页核对同账号、原游戏周的连续两帧积分及倒计时。已满可零局完成。达到上限且仍未满时，周回执标为 `exhausted`，计划结果为 `partial`。每次新开局沿用原账号、游戏周和发送前检查，失败、停止或跨周保留原意图及已核实胜利。

固定局数和积分目标共用同一账号／游戏周回执。积分意图绑定本地账号指纹、游戏周、开局上限及唯一意图。原生报告和账本记录同一意图，周回执绑定其原始字节及每次双帧积分图的哈希。

Windows 上，最后一次开局核验以仅允许共享读的句柄保护原意图、原生账本和积分双帧，直至输入提交返回。首次写周回执和每次共享锁重试都重新核对原游戏周和原意图，并从原件核验前到原子替换返回持有报告、账本及已绑定截图。重试等待前释放句柄。来源失效时保留待核对意图和已核实胜利。

同周已有完整或 `exhausted` 回执时，切换目标或调整设置会核对原件后返回原上限与结果。归属不符、原证据变化及缺少原生归属绑定的回执均保留为待核对。具备归属绑定的固定局数回执按原报告和证据复用。已核实的上限耗尽只结清原周预算，下一个游戏周可依到期条件另立目标。

父报告 `weekly_plan` 分列 `objective`、`maximum_runs`、原目标的 `completed_runs`、本次新增的 `new_completed_runs` 及 `points_capped`。复用时 `original_run_dir` 指向原子报告。本次积分读数详见差分子报告的 `periodic_points_goal`。积分目标本身不计作领奖。当前客户端的日常交接、积分读数和连续演算仍待实机。[验证记录](../VALIDATION.md#2026-11-06-差分周常周期积分目标)

## 货币战争周常后端

选择并启用`weekly_mode='currency_wars'`后，到期的“开始计划”与`--plan`执行货币战争周常。底层仍限标准A8财富造物主40开发流程与默认购买策略；实际完整玩法、其他模式及满额清理尚未验收。

界面只读核对本地原目标与来源，发现未完成目标后将每日主操作改为“继续周常”；若只剩周常审计，则显示“补存周常结果”。主按钮明确接续原目标，运行时重新执行后端门禁。日常摘要改为沿用原报告或本次不执行，周常摘要保留原周、原上限及已完成开发局数；当前未保存的每日／差分表单不改变原目标，也不阻止接续。游戏连接、识别及等待设置仍需有效。旧日常费用、实训和退出结果标明原日常；不把旧实训回执点亮为本次实训，也不在右上角当作本次新增消耗。原报告和失败证据保留。新目标与接续都不自动保存表单，不创建定时任务。

已核实整局失败也消耗原局数，周常及父计划分别保留`victories`、`defeats`和已结束数；失败结算不记为通关。未启用`currency_continue_after_defeat`时，留档后停止为partial，不自动领奖。`--plan --resume-weekly-currency`只确认该次失败停止并使用原剩余额度，不重复日常、不增加预算、不改冻结的自动继续设置；积分满分和奖励结清仍各须原生来源。规则及合成页面验证边界见[失败与接续](currency-wars-defeat-loop.md)。

保存设置中的`weekly_runs`在CW模式表示本周最多完成的新开发局数，范围1～10、默认1。达到积分上限可以0局结束，也可以少于上限提前完成。周常固定启用积分目标，不借用独立循环的`currency_runs`或`currency_until_points`修改周预算；记忆开拓者名与速通装备沿用已有偏好。以下是用法说明，未执行真实游戏操作：

# 接续原周常，复用原日常报告，不执行新的日常或增加预算

新目标在日常完成后读取新鲜账号、积分与倒计时，冻结开始时的游戏周和局数上限。旧单局或未结束循环在日常前阻止新计划，不接管历史开发局。同一账号／周已有未完成目标时，普通开始不重跑日常；明确接续复用原成功日常报告，其结果和消耗标为`daily_reused=true`、`budget_scope='original_daily_run'`，不表示本次又扣了一笔。已完整结束的周目标仍需先核对当前账号与积分，再查原始证据；改变星期、时间或上限不再开同周新预算。

周目标顺序复用已有积分Runner、有限循环及[独立领奖](currency-wars-weekly-notes.md)，每个正式输入继续核对窗口、UID、输入代次、冻结目标及原生账本。已核实的完整胜利才增加开发局数，已拥有满分仍会核对奖励。积分上限、当前可领取结清与独立整局验收分开，历史0/10不因周常完成而增长。任何未完成周目标会阻止其他输入Runner，所属子流程及明确的原生接续除外；只读识别可用，未知输入不重放。

| 结果 | 含义 |
| --- | --- |
| complete／already_complete | 当前目标的积分和奖励证据、原报告及周回执完整；后者不增加对局预算 |
| exhausted | 原上限已用完，已核实当前奖励，但积分仍未满；整体partial |
| expired | 原目标跨周后停止，不改成新周目标；整体partial |
| needs_review／stopped | 当前步骤、报告、领奖或回执尚未结束；已核实日常与局数保留 |

上限耗尽后，如果另一次当前观察证明积分后来增加，可保留原部分领奖回执，再只处理新增奖励；`later_points_observed=true`不说明额外积分由谁取得，原对局上限和完成数不变。助燃券满额仍停在独立领奖的blocked状态，不清理或重领。

周归属保存在原`currency-loops/<ID>/loop.json`的`weekly_plan`中，按账号／周的不可覆盖索引为`currency-weekly-index/<本地账号指纹>/<游戏周>.json`。每一局归档、连续回执链、原报告和证据均参与周常核对；领奖保留独立原生尝试。完成周回执为同循环目录`weekly.receipt.json`，绑定循环原件、原生领奖回执及周常报告哈希。原生步骤已完整结束但循环、周常报告或回执保存失败时，明确接续可只读补存新审计，不重发游戏输入；原失败文件、路径和存在时的哈希保留。整体计划报告失败不抹掉已经独立提交的周常完成事实。

父报告`weekly_plan.score_rewards_verified`表示已接受的CW周回执，`maximum_runs`、`requested_runs`与`completed_runs`使用原冻结上限及真实留档数。`currency_wars.mode='weekly_currency'`另含目标周、状态、阶段、子报告位置、原日常引用、只读恢复及后续积分观察标记。内部周常子报告成功但保存／提交失败时，整体周常不标为已验证。底层阶段事件带`currency_weekly_stage`，外层仍为weekly；暂停、停止及F9／F10在子流程和交接间隙传递。

2026-10-29，计划报告的`weekly_plan.daily_tasks`保存启动时选择的日常任务键，不从后来修改的表单反推。结果摘要仅显示对应日常字段及报告里实际出现的资源和核实结果；缺少或无效的旧范围字段沿用原展示。只安排未来周常时，后端success仍表示本次资格检查和报告保存结束，界面显示“本次无需执行 · 周常未到期”及冻结的北京时间，不把它写成周常完成。时钟到期后预览更新，原结果和报告保留，不自动运行。没有子执行阶段时不最小化窗口；进入日常或周常阶段仍按原方式让游戏保持前台。未选择的卡片在后端尚未给出结果时保持“未加入”，真实跳过结果仍按原报告显示。

## 去重与恢复

2026-10-30新增可选[多副本体力计划](power-plan.md)：`--plan --power-plan`或`PlanRunner(...,use_power_plan=True)`只替换日常中的刷本项，仍由一个正式日常Runner持有输入和资源预算。父报告保留子报告的`power_plan`，分项剩余次数与已确认资源不被周常覆盖。原单副本调用保持原义；仅保存计划条目不会让旧界面隐式执行多个副本。GUI接线及真实多副本→周常组合仍待验收，不因离线检查而标记为实机完成。

同日另接入[历战优先](echo-of-war-plan.md)，在显式体力计划内、用户条目之前执行，不增加`weekly_mode`选项，也不另开资源预算。资格按日常开始时间与04:00游戏周冻结；当前已用完与本次实际胜利次数分别保存。父报告的`power_plan.weekly_echo`保留这段原日常结果，后续差分／货币战争周常仍按已有流程处理。

`PlanRunner`顺序调用既有`Runner`。整段序列在外层共享执行租约和账号约束，每个子流程继续使用自己的互斥锁、前台检查、暂停、停止、资源账单和原始报告。暂停与停止跨阶段传递；子流程的finished事件不会提前解锁桌面或释放外层租约。总报告的`weekly_plan.children`保存各子报告位置。

2026-10-29补充运行反馈：日常子流程返回后立即显示已经核实的实训、实际副本次数与消耗，周常仍运行时不解锁设置。每个子事件携带阶段；周常自己的资源进度不会把日常消耗归零。差分局数只在原演算账单成功写入后更新，开始新尝试不增加完成数；暂停和继续保留当前阶段与局数。独立玩法保留已有日常卡片，修改日常计划会切回设置预览；单项详情不会覆盖总结果和错误。

差分子流程持有既有运行锁后，先返回已识别手机菜单，再从新画面核实账号。本地账号指纹仅用于`runs/weekly-plan/<账号指纹>/<游戏周>.json`；界面不靠历史账号报告点亮“本周已完成”。开局前以独占新建方式写入意图，写入失败不开始演算。

差分周回执要求原始报告、局数、难度核实以及开局、胜利、返回证据一致，并保存这些文件的哈希。固定局数须完成请求的局数。积分目标同时核对原上限和双帧读数。旧周的待核对意图、损坏记录、缺失或变化的原证据都会阻止新开局。差分人工核对后的接续仍使用原独立玩法入口，接续报告独立保留。

普通每日预算仍按每次运行计算，周计划不扩大开拓力、燃料、星琼或沉浸器授权；CW只使用冻结对局内已有的专用交易门禁。`--plan --new-battle-run`仅表示用户显式新增日常预算，不清旧账或周常待核对记录，不能与`--resume-weekly-currency`混用。
